C语言到机器：ABI、ELF、链接布局与启动证据

把结构体、调用约定、链接地址与启动代码连成一条可检查的证据链，解释优化后失效、移植失败和启动前崩溃。

GOALS

本章要交付什么

为一个含采样序号、时间戳和状态字的共享描述符写出显式布局契约，输出目标ELF与map审计表。

  • 计算结构体的偏移、对齐和尾部填充，区分内存布局与线协议
  • 用ELF头、段表、符号表和map文件定位代码及数据
  • 追踪Cortex-A9进入main之前的栈、数据段和异常向量初始化
  • 用最小反例证明越界、别名或整数溢出问题，并给出无未定义行为的修复

LEARN

机制、约束与验证

每条结论说明条件，每个实验保留可以复查的结果。

先建立四份契约

C源程序同时受语言标准、编译器选项、目标ABI和启动环境约束。语言决定表达式是否合法，ABI规定跨函数与跨目标文件如何交换数据，链接脚本规定地址，启动环境建立C运行需要的状态。能够编译只验证了其中一部分。为每个固件保存编译器版本、完整命令行、BSP版本、链接脚本和最终ELF；不要只归档BIN。

本课目标是Zynq-7000的32位Cortex-A9。先核对指针和long的实际宽度、大小端、ARM/Thumb、浮点调用约定，再链接第三方库。编译器支持浮点指令与函数参数采用硬浮点ABI是两件事。Linux用户程序的装载器负责许多初始化；裸机应用由BSP启动代码与前级引导共同完成，不能把两者的入口假设互换。本文引用的现行ABI用于查原则，2020.2工程仍须以本机工具链产物为准。

手算一次对象布局

在uint32_t对齐为4、uint16_t对齐为2的常见AAPCS32布局下，下面结构体的a在偏移0，b在4，c在8，最大对齐为4，末尾补齐到12字节。字段大小之和只有7。改为b、c、a后，偏移依次为0、4、6，总长通常为8。这里的“通常”必须由目标编译器的sizeof与offsetof证明，而非由主机电脑代答。

/* 可独立放入目标工程的检查片段；需包含stdint.h、stddef.h */
struct sample { uint8_t a; uint32_t b; uint16_t c; };
_Static_assert(offsetof(struct sample, b) == 4, "ABI mismatch");
_Static_assert(sizeof(struct sample) == 12, "unexpected layout");

packed可以消除某些填充，却可能制造未对齐访问和性能代价，不能把它当通用协议编码器。填充字节也不应参与memcmp或CRC。跨PS/PL共享描述符时，逐项声明字段宽度、字节序、对齐、保留位及所有权位；网络或文件中逐字节编码，不直接发送整个C对象。

函数边界不是源代码边界

AAPCS32基础约定用r0–r3传递部分参数和结果，其余可能入栈；更宽参数、结构体返回与VFP变体有额外规则。公共接口处SP必须满足8字节对齐，手写汇编保存一个4字节寄存器后直接调用C函数，可能破坏这个要求。被调用者应保存约定要求保留的寄存器，r9的角色依平台约定，不能照抄另一套启动模板。

排查“仅开启优化才错”时，先看声明与定义是否一致、是否省略函数原型、可变参数格式是否正确、汇编内联是否申明寄存器和memory破坏。利用objdump检查调用点的参数放置，再核对readelf的架构属性。hard-float库和soft-float对象混用，不能靠给链接器屏蔽错误来修好。ARM与Thumb互调也应交给正确的符号属性和链接器生成互工作跳板，不能把函数地址最低位随意清零后跳转。

ELF是可审计的装载说明

节描述编译链接的组织方式，程序头中的段描述装载器需要映射或加载的区域，二者不是一张表。.text通常含指令，.rodata含只读数据，.data有初始值，.bss通常是NOBITS：它占运行内存而不保存等长的零字节镜像。ELF文件变小不代表运行内存变少，调试信息变大也不代表板端RAM同样增加。

# 工具链终端中运行；前缀随实际安装调整
arm-none-eabi-readelf -h -l -S -A app.elf
arm-none-eabi-nm -n -S app.elf
arm-none-eabi-objdump -drS app.elf
# 链接时追加：-Wl,-Map=app.map,--cref

若数组声明为uint32_t ring[1024]且静态零初始化，应在bss及map中解释4096字节的运行占用。若栈向下增长而堆向上增长，map中两者符号相隔64 KiB，只能说明静态保留区间；还需最深调用链、中断嵌套和动态分配峰值的证据，不能据此宣称永不碰撞。

链接脚本与启动代码必须配对

VMA是运行地址，LMA是镜像中的装载地址。若.data运行在RAM但初值放在非易失介质，某个明确的装载阶段必须把初值复制过去；如果ELF加载器已经放好数据，启动代码未必再复制。bss清零、各异常模式栈、向量基址、MMU/缓存状态与C库初始化也要逐项找到责任方。Cortex-A9不采用Cortex-M那种“首字为初始SP”的向量表规则。

/* 链接脚本示意片段，不能替换BSP完整脚本 */
.data : { __data_start = .; *(.data*) __data_end = .; } > RAM AT> FLASH
__data_load = LOADADDR(.data);
.bss (NOLOAD) : { __bss_start = .; *(.bss*) *(COMMON) __bss_end = .; } > RAM

对已有2020.2工程，从实际生成的lscript.ld、boot.S、crt0路径和FSBL日志追踪到main。把停点设在入口、bss清零后与main，观察同一个全局变量。调试器加载一次后“正常”、冷启动却失败，常说明调试下载或前一轮运行替启动链完成了缺失步骤；必须断电重启复核。

优化器不会替未定义行为兜底

有符号溢出、越界、释放后使用、违反有效类型的指针重解释都可能让优化结果偏离直觉。int计数器加到INT_MAX后，不能假定自然回绕。无符号回绕有定义，却仍需证明业务正确。移位次数不能为负或达到类型位宽；把uint8_t左移前还要注意整数提升。volatile约束特定访问行为，不会修复越界、数据竞争或跨核同步。

/* 完整的4字节小端读取函数：调用者保证p至少有4字节 */
static uint32_t load_le32(const uint8_t *p) {
    return (uint32_t)p[0] | ((uint32_t)p[1] << 8) |
           ((uint32_t)p[2] << 16) | ((uint32_t)p[3] << 24);
}

读协议字段时先检查剩余长度，再用这种组装或memcpy到对齐局部对象，必要时做端序转换。检查count * item_size时先比较count是否超过SIZE_MAX / item_size，不能等乘法溢出后再判断。为失败输入保留原始字节、优化级别、告警与反汇编，形成可重复的缺陷证据。

从布局模型走向板上证据

本章布局交互演示.text、.data、.bss和stack的ROM/RAM预算以及启动步骤，不执行目标编译器或链接器。给.data增加4 KiB，它既可能增加镜像初值占用又增加运行RAM；给.bss增加4 KiB则主要增加运行占用。这里的ROM是存储预算抽象，实际ELF加载、压缩镜像和FSBL布局应另行核对。结构体字段重排需要前述目标sizeof与offsetof实验验证。

建立三组构建：诊断构建使用告警与调试信息，发布构建保留实际优化，主机可移植核心构建加入可用的UB/地址检查。主机检查不能证明目标ABI正确，板端运行成功也不能证明无未定义行为。最终交付一张“源符号→ELF节→装载段→运行地址→初始化责任方”的表，以及一个能在冷启动与热复位重复执行的断言实验。用这张表解释一次异常PC落在数据区、初值错误或栈越界，才算贯通了C到机器的路径。

工程任务 · 为一个含采样序号、时间戳和状态字的共享描述符写出显式布局契约，输出目标ELF与map审计表。

在目标工程加入sizeof/offsetof断言；分别检查readelf节表与程序头，单步确认bss和全局初值何时建立。

故障练习：在实验分支中去掉一个函数原型或故意错误声明参数宽度，先用告警定位再用反汇编解释；不要烧录未审计固件到生产板。

验收：结构体断言通过；每个运行区间都有map及初始化责任方；断电冷启动和调试下载的全局初值一致；不存在用关闭优化掩盖的问题。
