38.1 先做数据预算，再选 DMA

DMA 把逐字搬运交给硬件，但配置、中断、缓存维护和消费数据仍要 CPU 参与。不能把“硬件搬运”写成“整个系统 CPU 占用约等于零”。GP 接口也不等同于 AXI4-Lite；本课程的自定义控制寄存器常采用 AXI4-Lite 从设备。

用途典型通路先核对什么
控制与状态PS M_AXI_GP → AXI-Lite 寄存器地址、访问属性、握手、软件开销
批量流采集AXI DMA S2MM → PS S_AXI_HP → DDR背压、包尾、缓冲、一致性、持续消费能力

64 bit × 100 MHz 的接口原始上限是 800 MB/s；它是算术上限，不是本板实测。有效吞吐取决于协议开销、IP 配置、DDR 竞争和软件。先完成下方带宽与缓冲模型，再测真实系统。

38.2数据链路与 BD 搭建

TEXT
[自制 Stream 数据源]──axis──▶[AXI DMA S2MM]──S_AXI_HP0──▶ DDR 环形缓冲区
 (如 32bit 递增计数器)          ▲ M_AXI_GP0 配置/状态寄存器
                                ▲ irq → IRQ_F2P[1]
  1. BD 中添加 AXI Direct Memory Access：只勾 Enable Read Channel? 否——只勾 Write Channel(S2MM)；Disable Scatter Gather（先用 Simple 模式）；Width of buffer length register=23（最大 8MB/次）；
  2. S_AXIS_S2MM 接你的数据源（教学可用自写的 32 位递增计数器 axis 模块：TVALID 可持续有效；数据与包计数只在 TVALID && TREADY 时前进，第 4096 个接受拍携带 TLAST，背压时保持数据与 TLAST）；
  3. M_AXI_S2MM 连到 ZYNQ 的 S_AXI_HP0（Run Connection Automation 自动加 SmartConnect）；
  4. ZYNQ PS 勾选 S_AXI_HP0；irq_s2mm → xlconcat 第二输入 → IRQ_F2P[1]；导出 XSA。

38.3 Simple S2MM：状态位、复位与完成判定

先核对 IP 生成参数与 PG021。S2MM_DMASR 位 1 是 Idle，位 12 才是 IOC_Irq；Idle 不能单独证明你刚提交的包成功完成。DMACR 位 2 是 Reset，把整个寄存器写 0 只是停止运行，不是复位。

TEXT
Simple S2MM 的控制顺序（流程说明，不是完整驱动）：
1. 由驱动拥有通道；需要复位时写 DMACR.Reset=1，并带超时等待该位自清。
2. 读取 DMASR，检查 Halted 与错误状态；清除旧的 IOC/IRQ 状态（W1C）。
3. 准备设备可访问的 DMA 缓冲，完成所有权与缓存同步。
4. 设置 RS，写目的 DMA 地址，最后写合法的非零 LENGTH。
5. 等待本次完成中断/IOC，同时检查 DMAIntErr、DMASlvErr、DMADecErr。
6. 等待有截止时间；失败时停通道、收集状态，再按驱动规定恢复。
7. CPU 接管完成的缓冲后再读数据，并核对序号、字节数与包尾。

寄存器地址示例随本工程地址表变化。Linux 正式数据通路优先采用内核驱动/DMAengine；UIO 不自动完成缓冲分配、缓存同步和 DMA 生命周期管理。不要同时让用户程序与内核驱动操作同一通道。

38.4 DMA 地址、缓存与缓冲所有权

CPU 虚拟地址、CPU 物理地址与设备 DMA 地址是不同概念。Linux 驱动应使用 DMA API 返回的 dma_addr_t；不能把 malloc 指针交给 DMA。Simple 模式的一块目标缓冲须在设备可见地址空间中连续，SG 模式则由描述符描述分段。

设备树 reserved-memory 只表达保留内存的安排，不会自动把它变成可用的 UIO/DMA 缓冲；映射、分配与设备绑定还需相应驱动。no-map 与 reusable 不能作为含糊的二选一伪语法留在可复制节点里。

HP 通路不提供与 A9 Cache 的自动一致性。Linux 的一致映射可用 dma_alloc_coherent；流式映射通过 dma_map_*、dma_sync_*、dma_unmap_* 交接。O_SYNC 是打开标志，不能跨驱动保证映射属性或 DMA 正确性；volatile 也不能替代缓存同步。

TEXT
TX / DMA_TO_DEVICE：CPU 填充 → map 或 sync_for_device → 设备读 → 完成 → 收回所有权
RX / DMA_FROM_DEVICE：准备/交给设备 → 设备写 → 确认完成 → unmap 或 sync_for_cpu → CPU 读取
重复使用 streaming 映射：遵守同一设备、方向、长度和映射生命周期；设备拥有期间 CPU 不访问。
coherent 缓冲：不等于免同步协议；描述符发布顺序仍可能需要内存屏障。

详见 Linux DMA mapping Guide。裸机驱动示例中的缓存维护调用也不能直接移植成 Linux 用户态操作。

38.5 环形缓冲：先交接，再复用

轮流写 N 个数组不等于正确环形缓冲。每个槽位都要有所有权与序列号，消费者没读完就绕回覆盖，会得到“新元数据配旧内容”或静默丢帧。

TEXT
FREE → DEVICE_OWNED → READY(seq, length, status) → CPU_OWNED → FREE
生产者：只取 FREE 槽；提交 DMA；完成后发布 READY。
消费者：领取 READY；完成 CPU 同步；读取并校验；归还 FREE。
没有 FREE：实施背压，或按已声明策略丢弃并递增丢包计数。
错误/取消：先确认设备停止访问，再回收槽位；不能直接释放仍在 DMA 中的内存。

在下方 FIFO 模型中让消费者暂停，验证“已接受数据 = 已消费数据 + 缓冲剩余”。实际实现还需针对并发、内存可见性、设备重启和序号回绕设计同步。

38.6 用同一口径测吞吐、CPU 与正确性

测试先固定数据宽度、时钟、包长、缓存策略、样本数和 DDR 负载。数据源用递增序号，端到端逐字校验；只统计字节数无法发现重复与乱序。

  • 有效吞吐 = 成功交付的 payload 字节 / 测量区间；注明十进制 MB/s 与是否含初始化。
  • CPU 开销包括提交、IRQ、同步与消费，分别测轮询和中断，不写“DMA = 0% CPU”。
  • 同时报告丢包、错误、最大缓冲水位与消费者暂停恢复结果。
  • 原稿的 600–750 MB/s 等数值无本板测量记录，改为待实验验证的目标范围，不能当成既成实测。

常见问题 FAQ（避坑指南）

Q1：DMA 写完数据全是旧值？

Cache 一致性问题（38.4②）。确认缓冲区 non-cacheable 映射，或在内核侧做 invalidate。这是 DMA 类问题第一嫌疑。

Q2：传输卡死在 IOC 不置位？

① 数据源 tvalid 从未拉高（源头没发）；② LENGTH 为 0 或超过本 IP 配置允许的长度；③ HP 连接、时钟或复位错误导致写事务无法完成；④ 忘记先置 RS 再写 LENGTH；⑤ 缺少正确 TLAST 或接收包超容量。长度上限由生成参数决定，排查必须同时读取错误状态并设置超时。

Q3：地址没对齐报错？

AXI DMA 要求目的地址按数据位宽对齐（64bit 模式 8 字节），长度同理。用 0x8 对齐分配；SG 模式描述符还有 64 字节对齐要求。

38.7 SG 与循环传输：不要猜描述符位

SG 的描述符结构、对齐、控制位和状态位以所用 PG021/驱动版本为准。优先从官方驱动的 BD ring API 建立流程，不要把 MM2S 的包控制位直接用于 S2MM。

TEXT
分配并对齐 BD ring → 初始化下一描述符与缓冲 DMA 地址
→ 填写该方向合法的控制字段 → 按驱动要求同步描述符
→ 将一段 BD 提交硬件 → 回收完成 BD、检查状态和实际长度
→ 处理/归还缓冲 → 重新提交空闲 BD
普通 SG ring 与 cyclic 模式不是同一配置；不能凭“最后一项指回第一项”就假定可无限循环。

缓冲区长度字段位宽是 IP 配置参数，最大值为 (2^width − 1)，不能把“8 MB”当作所有配置的统一上限。接收端 TLAST 必须对应合法包尾，发生在 VALID 与 READY 同时有效的接受拍。

38.8 Linux DMAengine：映射与提交各司其职

以下是调用流程片段，省略模块骨架；每步失败都须有回收路径，不能直接拼成可加载模块。

TEXT
chan = dma_request_chan(dev, "rx");              // 检查 IS_ERR
map_dev = dmaengine_get_dma_device(chan);         // 映射必须使用 DMA 控制器的设备
mapped_nents = dma_map_sg(map_dev, sgl, orig_nents, DMA_FROM_DEVICE);
// mapped_nents == 0 表示映射失败
// prep 使用映射返回的 mapped_nents；unmap/sync 使用原始 orig_nents
transaction = dmaengine_prep_slave_sg(chan, sgl, mapped_nents,
                                     DMA_DEV_TO_MEM, DMA_PREP_INTERRUPT);
// 检查 NULL；注册回调；submit 后检查 dma_submit_error(cookie)
// issue_pending；带超时等待；失败先 terminate_sync，再回收映射。
// 完成后通过 unmap 或 sync_for_cpu 交还 CPU，再读取数据。

先读 DMAengine client 文档，再核对本板驱动、设备树 dma-names 与内核版本。DMA 映射不是无限生命周期的“设置一次就不用管”。

38.9 分清 PS DMAC、AXI DMA 与 AXI CDMA

  • PS 内置 DMAC：Zynq-7000 处理系统中的 Arm PL330 控制器，是 PS 固有资源，见 UG585。
  • AXI DMA：在 PL 中实例化的 IP，提供 AXI memory-mapped 与 AXI-Stream 之间的 MM2S/S2MM 传输，见 PG021。
  • AXI CDMA：在 PL 中实例化的 Central DMA IP，用于 memory-mapped 到 memory-mapped 传输；不能把它称作“PS 内置 CDMA”。

一致性由所接通路、事务属性、内存属性及软件维护共同决定。连接 ACP 也要满足接口的事务与配置要求，不能据 IP 名称推出“自动正确”。Linux 驱动使用 DMA API，而非直接调用未导出的私有 Cache 维护函数。

依据：UG585：DMAC 的 Arm IP Core。
