01

先选对型号：7020 站在哪一档

ZYNQ-7000 不是一颗芯片，而是一个家族。它们的 PS 几乎完全一样，差别主要在 PL 的规模。 理解这一点，你就不会再把「7020」当成一个孤立的型号，而是知道它在资源阶梯上的位置。

The Constant

PS 是家族里的「常量」

7010、7020、7030、7045 都共享同一套双核 Cortex-A9 处理系统： 同样的 NEON/FPU、512KB L2、256KB OCM、DDR 控制器和 I/O 外设。 所以你在 PS 侧写的裸机代码、Linux 驱动，换型号时通常不用重写。

The Variable

PL 才是家族里的「变量」

从 7010 到 7045，LUT 数量从 1.76 万涨到 21.86 万，BRAM 与 DSP 也成倍增加。 做选型时，先估算 PL 侧要放多少逻辑、多少缓存、多少乘法器，再看 PS 的外设是否够用。

APU：跑软件的那一半

双核 Cortex-A9、NEON/FPU 与 512KB L2 缓存，负责 Linux、协议栈、界面和上层业务。它是「智能」的一端。

Linux协议栈非实时
!
一个常见误解：PL 不能绕过 PS 的 DDR 控制器直接访问内存条。 PL 访问 PS DDR 的常见高吞吐路径是 S_AXI_HP 端口；也可根据需求通过 ACP 或 S_AXI_GP 等可达路径经 PS 互联访问，具体见 UG585； 这也是为什么高带宽采集系统通常要配 DMA，而不是让 CPU 一笔一笔搬。
03

PS：被低估的完整 SoC

PS 不是「单片机 + FPGA 胶水」，而是一颗带有 MMU、Cache、DDR 控制器和完整外设子系统的应用处理器。 它能独立跑 Linux，也能在裸机模式下给出确定性响应。

互动实验 03

PS 子系统探针

切换四个子系统，看看每一块在真实项目里负责什么。

APU · 应用处理
Application Processing Unit

双核 Cortex-A9：Linux 的落脚点

每核带 NEON SIMD 与 VFP 浮点单元，32KB L1 指令/数据缓存，两核共享 512KB L2 与 SCU 一致性单元。 领航者板卡上的 -2 速度等级最高 767MHz，跑无桌面 Linux 非常从容。

  • 双核共享 L2，是 SMP Linux 的基础
  • NEON 加速图像、滤波与批量数据处理
  • 每核私有定时器与看门狗，另有全局定时器
2×Cortex-A9
512KB共享 L2
767MHz-2 速度等级
Memory Path

DDR 是唯一物理入口

PS 的 DDR 控制器支持 DDR3/DDR3L/DDR2/LPDDR2。PL 访问板上的 PS DDR 时须经过 PS 互联及 DDR 控制器，常用 S_AXI_HP 做批量访问，也可使用满足要求的 ACP 或 S_AXI_GP 路径。外接 PL 存储器属于另一种硬件设计。板载容量以本板资料为准。

Fast Memory

OCM：256KB 的片上存储区

片上 SRAM 不经过 DDR 控制器，通常可降低对外部 DDR 的依赖，但访问延迟仍受端口、仲裁和时钟等影响，不能笼统保证零等待。FSBL、启动早期代码、实时性苛刻的中断向量或热代码常放在这里。

Boot

BootROM：上电的第一段代码

芯片出厂固化的 128KB BootROM 决定启动介质和第一阶段加载方式。它不存放在你的工程里，也不能被改写。

i
背下两个常用基地址：GPIO = 0xE000A000， UART1 = 0xE0001000。领航者的调试串口通常接 UART1； 后面裸机点灯、串口打印、Linux 设备树都会反复遇到它们。
04

PL：一块可以「长」出电路的硅片

PL 的资源不是抽象分数，而是四种很具体的积木：查找表、触发器、块存储和 DSP。 你写的每一行 Verilog，最后都要落进这几类资源里。

Logic

LUT6 · 53,200

任意 6 输入组合逻辑的「万能门」。译码、比较、状态机次态逻辑，最终都会映射到 LUT。

State

FF · 106,400

每个触发器存 1 bit 状态。计数器、流水线寄存器、握手信号，都靠它在时钟沿保持数据。

Memory

BRAM · 140 × 36Kb

约 4.9Mb 的双口块存储，适合 FIFO、行缓存、查找表和跨时钟域缓冲。

Math

DSP48E1 · 220

25×18 乘加硬核。FIR、矩阵运算、坐标变换用它，比用 LUT 拼乘法器更省资源也更快。

Clock

CMT · 4 组

每组含 MMCM 与 PLL，可倍频、分频、移相。PL 内部不同时钟域的分频与相位关系在这里生成。

Analog

XADC · 双 12bit

1MSPS，可测片内电压与温度，也能接外部模拟输入。软 PLC 的模拟量采集可以从这里起步。

05

PS-PL 互联：五类通道怎么选

这是全章最值得形成肌肉记忆的一张表。选错通道，系统可能「能跑但很慢」，甚至出现缓存不一致。 先记住一句话：控制走 GP，大流量走 HP，缓存一致走 ACP，事件走 IRQ。

通道 方向 位宽 典型用途 本课程使用点
M_AXI_GP0/1 PS → PL 32 / 64b CPU 读写 PL 侧 IP 寄存器，AXI-Lite 为主 第 9 章起所有自定义 IP 的控制口

IRQ_F2P[15:0] PL → PS 16 根中断 事件通知，不承载数据搬运 PLC IO 引擎的上报与故障中断
Auxiliary

别忽略辅助信号组

除了 AXI，PS 还向 PL 提供 FCLK_CLK0~3 时钟、 FCLK_RESET0~3 复位，以及 16 根 IRQ_F2P 中断。 软 PLC 的 IO 引擎通常就是「FCLK + AXI-Lite + IRQ」三件套。

Bandwidth Sense

GP 不是数据搬运通道

GP 端口为寄存器访问优化，适合控制类小数据。连续 ADC 流、视频帧这类吞吐型任务如果硬走 GP， 仲裁延迟和 CPU 参与会把有效带宽拉得很低。此时应该让 PL 通过 HP 直接写 DDR。

06

地址空间：软件眼里的芯片地图

在 C 语言里，访问硬件本质上就是读写某个固定地址。你要知道哪个地址归 PS 外设、哪个窗口留给 PL、 哪个范围是 DDR。否则调试时看到「读回来全是 0」或「一写就挂」，很难判断是自己写错还是地址压根不存在。

07

四种开发模式：你该走哪条路

同一块 ZYNQ，可以只当 FPGA 用，也可以当 ARM 单片机用，还可以跑 Linux，甚至让两个核各干各的。 模式没有优劣，只有是否匹配任务。

纯 FPGA
Pure FPGA · Vivado

只用 PL：把 ZYNQ 当一块 FPGA

第 5–6 章

Verilog 描述电路，Vivado 综合、布局布线并生成 bitstream，通过 JTAG 烧写到 PL。 PS 可以完全不参与，适合纯逻辑、高速接口和实时信号处理实验。

Verilog→综合→实现→bitstream
优势：时序确定、无 OS 抖动 代价：没有网络与文件系统 产出：.bit / .bin
Bare Metal

裸机不是「低级」，而是「可控」

PS 裸机直接用 C 操作寄存器或使用 Vitis 库，没有进程调度和页表干扰。 中断延迟、启动时间、内存占用都可预测，适合做启动链验证、板级自检和硬实时控制。

Soft PLC

软 PLC 为什么选 Linux + PL？

Linux 负责梯形图解释、Modbus TCP、Web 服务和日志；PL 负责微秒级 IO 采样、PWM 与故障联锁。 PS 与 PL 通过 AXI 寄存器和中断协作，既拿到生态，又保住硬实时。

模式判断小练习

步进电机脉冲要求频率稳定、抖动极小，放 PS 还是 PL？

参考：放 PL。用计数器/分频器生成脉冲，CPU 只通过 AXI-Lite 写周期、占空比和使能位；需要停止时再读状态或收中断。

产品需要 Web 配置页、Modbus TCP 和 SD 卡日志，选哪种模式？

参考：Linux。网络协议栈、文件系统、Web 服务都是 Linux 的强项；实时 IO 再交给 PL 或内核实时线程补足。

核 0 跑 Linux 做人机界面，核 1 跑裸机做毫秒级控制，这叫什么？

参考：AMP（非对称多处理）。两核运行不同软件栈，通过共享内存与 IPI/rpmsg 通信。它是第 40 章的进阶方向，不是入门必选项。

电源域与时钟树：上电之前先看底层

很多「板子没反应」「串口乱码」「PL 不工作」的根因，不在代码，而在电源顺序、Bank 电压或时钟源。 这一节把硬件层的两条主线补上：电从哪来，时钟从哪来。

CLOCK 33.333MHz → 三个 PLL
PS 参考时钟

板载 33.333MHz 晶振进入 PS，三个 PLL 分别服务 ARM、DDR 和 IO 外设。它是整颗芯片的节拍起点。

I/O Voltage

MIO 电平由 VCCO 决定

MIO 分成不同 Bank，每个 Bank 有自己的 VCCO。MIO Bank 是 3.3V 还是 1.8V，直接决定外设电平和 SLCR 配置。 PL 侧的 IOSTANDARD 也必须与对应 Bank 的 VCCO 一致，否则轻则通信失败，重则损伤 IO。

Clock Domain

FCLK 是 PL 的节拍，也是 CDC 的起点

Vivado 的 PS 配置页可以设置 FCLK_CLK0~3 的频率，它们来自 IO PLL。PL 内部再用 MMCM/PLL 分频或倍频。 跨时钟域传递计数值、握手信号时，必须按第 22 章的 CDC 纪律处理，不能直接打两拍就万事大吉。

!
掉电丢失不是 bug：FPGA 的配置信息保存在 SRAM 中，掉电即失。产品化时必须由 PS 启动链从 QSPI Flash 或 SD 卡加载 bitstream， 最终打包成 BOOT.BIN。JTAG 烧写只适合调试，不适合量产交付。

9.3 思考题（附参考思路）

1. 设计「100kHz、4 通道应变片采集 + 上位机曲线」系统，采集链路放 PS 还是 PL？数据怎么回传？

参考思路：4 通道 100kHz 要求并行采样和确定性时序，放 PL 最合适。PL 内完成采样、滤波和打包， 先写入 BRAM/FIFO，再通过 S_AXI_HP + DMA 成批搬到 DDR。 PS 上的 Linux 负责协议、存储和 Web 曲线显示。这样 PL 保证采样节拍，PS 负责「智能」。

2. 查 UG585 附录 B，找到 GPIO 的 MASK_DATA_LSW 寄存器偏移，计算绝对地址。

参考思路：先确认 GPIO 控制器基地址是 0xE000A000， 再在 UG585 附录 B 的 GPIO 寄存器表中找到目标 Bank 的 MASK_DATA_LSW 字节偏移， 绝对地址 = 基地址 + 偏移。不要把教程里的示例偏移当成所有 Bank 通用；以你使用的文档版本和 Bank 编号为准。

3. 步进电机脉冲要求频率精确稳定，放 PS 还是 PL？CPU 如何设定频率和使能？

参考思路：放 PL。PL 用计数器/分频器产生脉冲，抖动只取决于时钟质量； CPU 通过 M_AXI_GP + AXI-Lite 写预分频、周期、占空比和使能位， 再通过 IRQ_F2P 接收完成或故障事件。不要用 Linux 用户态软件定时器直接生成脉冲。
