01

为什么是 ZYNQ？

先把这颗芯片当成一支团队：PS 是能跑 Linux 的「大脑」，PL 是可以按需定制的「反射神经」。 它们不是简单拼在同一块板子上，而是通过片内 AXI 总线共享内存与带宽。理解这套分工，是后面所有设计决策的起点。

Processing System

PS · 处理器系统

双核 Cortex-A9，带 MMU、L1/L2 Cache、NEON/FPU、DDR 控制器与丰富外设。它是一颗完整的 SoC，可以直接运行 Linux。

擅长：复杂软件、协议栈、界面、文件系统。

Programmable Logic

PL · 可编程逻辑

Artix-7 级别的 FPGA 结构：LUT、触发器、BRAM、DSP。你把电路「画」进去，它就以硬件速度并行工作。

擅长：并行计算、硬实时 IO、确定性时序。

Interconnect

AXI · 片内互联

多条 AXI 通道把 PS 与 PL 连成一个整体，带宽可达数 GB/s。CPU 读写 PL 寄存器，PL 也能直接成批访问 DDR。

一句话：同一颗芯片里的两个部门，共享仓库与高速公路。

和「CPU + FPGA 板级组合」差在哪？

方案组成通信方式结果
CPU + FPGA 两块板 STM32 / 工控机 + 独立 FPGA SPI、PCIe、并口等板间通信 延迟大、带宽低、PCB 复杂、功耗和体积都上去了
ZYNQ 单芯片 ARM 处理器系统 + FPGA 逻辑，同一颗 die 片内 AXI 直连，共享 DDR 纳秒级延迟、高带宽、低功耗、体积小，适合工业控制/机器视觉/软件无线电
i
分工口诀：PL 负责「快」，PS 负责「智」。 但真实系统往往是两者协作：PL 把硬实时、重复、并行的活干掉，PS 处理协议、业务、界面和存储。 纯 PS 做纳秒级 PWM 会被中断和调度抖动影响；纯 PL 做 TCP/IP 和 Web 又会又贵又难维护。

预备知识 I：数字电路与 FPGA

你不需要先学完一整本数电。下面这些概念会在第 5、6、9、21、22 章反复出现： 先用直觉建立起来，后面边做边补细节。这一节配有 5 个可交互的小实验。

5.1 数制与码制：硬件的母语

二进制是硬件的母语；十六进制只是「4 位一组」的速记。比如 0xF3 = 1111_0011， 一眼就能互换。十进制转二进制则用「短除取余」。补码是另一个必须跨过的坎： 正数不变，负数取反加一；8 位范围是 -128 ~ +127。 硬件的加减法共用一套加法器，靠的就是补码。

5.2 组合逻辑四大件

组合逻辑没有记忆：输出只取决于当前输入。你写的 if-else、case， 综合之后就是 MUX、译码器、比较器这些硬件。记住一句话：Verilog 不是写程序，而是描述电路。

Decoder

译码器

n 位输入选通 2ⁿ 个输出之一。地址译码、片选、七段数码管驱动都用它。

MUX

多路选择器

数据流开关，是 if-else 的硬件化身。选择信号决定哪一路数据通过。

Adder

加法器

行波进位慢、超前进位快。「面积换速度」的第一个例子，也是流水线设计的动机。

Comparator

比较器

大小判断。位数一多，级联链就容易成为时序违例的常客（第 22 章会切流水线）。

5.3 时序逻辑：让电路「记住」状态

Register Bank

n 个 FF 并排就是 n 位总线打拍。流水线切割、跨时钟域同步都靠它。

5.5 FPGA 到底是什么？和 MCU 有什么本质差异？

MCU 是「顺序执行指令流」，FPGA 是「并行电路同时工作」。 你把 HDL 写下去，综合工具把它翻译成 LUT/FF，布局布线放进真实器件，最后生成比特流配置 SRAM。 注意最后一步：FPGA 的配置掉电就丢，每次上电都要重新加载 bitstream。

「函数」复用 CPU 指令复制一份新电路

预备知识 II：C 语言内功

嵌入式 C 的难点不是语法，而是你知道编译器把你的代码变成了什么。 这一节只挑后续驱动、协议解析、PLC 运行时真正用得到的部分：存储类别、指针、关键字、位操作、联合体与未定义行为。

Linux 驱动的 file_operations、命令分发表、PLC 指令解释器，本质都是函数指针表。

!
第四层：void* 泛型与别名陷阱。用 char * 逐字节搬运最安全； 不同类型指针互访可能违反 strict aliasing，是未定义行为。协议解析请用 memcpy 或 packed struct， 不要直接强转结构体指针。

6.3 关键字深挖：面试与调试高频

volatile

每次强制真实访存

告诉编译器「这个值可能被外部改变，不许缓存优化」。但它不提供原子性，多核/中断共享数据仍需锁或关中断。

const

只读承诺

修饰变量、指针或函数参数，表达「不该被改」。注意 const int *p 与 int *const p 是两回事。

static

三种用法

函数内静态变量（有记忆）、文件级私有函数/变量（内部链接）、C++ 类静态成员。嵌入式最常用前两种。

inline

建议内联

只是给编译器的建议，现代编译器自己会决定。头文件里最稳的写法是 static inline。

restrict

承诺指针不重叠

给编译器优化空间，常见于 memcpy 原型。承诺错了，行为未定义。

volatile + 锁

为什么不能互相替代

volatile 只保证「每次真读真写」，不保证「读-改-写」是一个不可分割的动作。计数器和标志位尤其要小心。

!
必须两者同用的场景：中断服务程序修改一个 32 位计数器，主循环读取并清零。 变量要加 volatile 防止缓存，但「读取 + 清零」仍可能被中断打断，还需要关中断或原子操作保护。

6.4 位操作：寄存器编程的日常

裸机开发和驱动开发，很大一部分工作就是「把某一位设 1、清 0、翻转、读取」。 先记住这组宏，再玩下面的 32 位实验：

C · bit macros
#define BIT(n)          (1u << (n))
#define SET(x, n)       ((x) |=  BIT(n))
#define CLR(x, n)       ((x) &= ~BIT(n))
#define TGL(x, n)       ((x) ^=  BIT(n))
#define GET(x, n)       (((x) >> (n)) & 1u)
/* 要求 BIT 的 n < 32；构造满 32 位掩码时不能执行 1u << 32。 */
static inline uint32_t mask32(unsigned lo, unsigned hi)
{
    if (lo > hi || hi >= 32) return 0;
    return (UINT32_MAX >> (31u - (hi - lo))) << lo;
}
#define MASK(lo, hi) mask32((lo), (hi))

/* 统计 1 的个数：while (v) { v &= v - 1; count++; } */

packed struct

协议解析：禁止编译器插洞

C · packed frame
struct __attribute__((packed)) canframe {
    uint32_t id;
    uint8_t  dlc;
    uint8_t  data[8];
};
/* 关键字段仍建议手动移位解析，
   位段跨端序不可移植 */
!
对齐的坑：编译器会在成员之间插入 padding，让访问更快，所以 sizeof(struct) 可能大于字段之和。 packed 能去掉 padding，但可能带来非对齐访问；关键协议字段用手动移位最稳。

6.6 X-Macro：一处定义，处处生成

工业代码里常有一份「寄存器列表」：既要枚举编号，又要字符串表，还要生成处理分派。 手写三份很容易不同步。X-Macro 用一份列表生成全部，改一行宏，三处同步更新。

C · X-Macro
#define PLC_REG(X) \
    X(ID,    0x00, R) \
    X(CTRL,  0x04, RW) \
    X(DI,    0x08, R)

/* 枚举 */
enum {
#define E(n, a, p) REG_##n,
    PLC_REG(E)
#undef E
};

/* 字符串表 */
static const char *reg_names[] = {
#define S(n, a, p) #n,
    PLC_REG(S)
#undef S
};
/* 加一个寄存器 = 改一行宏，杜绝手滑不同步 */

6.7 未定义行为（UB）与 MISRA C

UB 是编译器优化的「合法谋杀」：一旦代码触发未定义行为，编译器可以假定它永远不会发生， 于是删掉你的判空、判溢出分支。嵌入式里最危险的是「平时能跑，换优化等级就崩」。

UB Checklist

高频未定义行为

  • 有符号整数溢出（INT_MAX + 1）
  • 移位数 ≥ 位宽，或负数左移
  • 同一变量两次修改之间无序列点（i++ + ++i）
  • 解引用空指针 / 野指针
  • 越界一格的循环写（i <= n）
  • 写字符串字面量；返回局部变量地址
Defense

对策三板斧

  • 编译期：-Wall -Wextra -Werror
  • 测试期：-fsanitize=undefined,address
  • 评审期：对照 UB 清单逐项检查

MISRA C 的动机是可分析性与功能安全：限制动态内存、递归、隐式转换、魔数等， 为第 44 章 SIL 认证流程打基础。理解动机比死记条目重要。

7.1 Cortex-A9 程序员模型速览

Registers

通用寄存器与特殊角色

  • R0–R12：通用寄存器；R0–R3 传参 / 返回（AAPCS）
  • R13 = SP：栈指针，C 环境的前提
  • R14 = LR：链接寄存器，保存返回地址
  • R15 = PC：程序计数器，当前执行位置
  • CPSR：N/Z/C/V 标志 + 处理器模式 + 中断屏蔽 I/F
Modes

处理器模式与专属栈

User、IRQ、FIQ、SVC（复位与 SWI）、Abort、Undef、System。异常各有专属 SP，这是向量表分工的基础。

记住：模式切换时，栈也会切换；写裸机中断时，这是第一个要处理的问题。

7.3 AAPCS：C 与汇编的契约

8.3 思考题（附参考思路）

1. 设计一个「100 kHz、4 通道应变片采集 + 上位机曲线显示」系统，采集链路放 PS 还是 PL？数据怎么回传？

参考思路：4 通道 100 kHz 采样要求并行、确定性时序，放 PL 最合适。PL 内做并行采样与滤波， 数据先写入 BRAM / FIFO，再通过 S_AXI_HP + DMA 成批搬到 DDR。 PS 上的 Linux 负责协议、存储与 Web 曲线显示。这样 PL 保证采样节拍，PS 负责「智能」部分。

2. 实验现象与教程不一致时，你会按什么顺序排查？为什么？

参考思路：先版本与环境（Vivado/Vitis/PetaLinux 版本、许可证、驱动），再硬件连接（电源、USB、JTAG、串口、网线、启动拨码）， 再工程配置（器件型号、引脚约束、bitstream 是否最新），再代码逻辑，最后才怀疑文档或芯片。 理由：先排除「环境与硬件」这类系统性因素，再用二分法缩小到具体模块；否则容易在错误的层面上越查越乱。

3. 查阅 UG585 目录，Chapter 3 与 Chapter 29 各自回答什么问题？
