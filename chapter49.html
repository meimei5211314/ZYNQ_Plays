49.1 先固定平台支持，再做 A9 AMP

本章目标是理解 Cortex-A9 上的 FreeRTOS 移植和可测量周期任务。Zynq-7000 是双 Cortex-A9，不是 Zynq UltraScale+ 的 A53/R5 组合；不能照搬后者的 RPU 固件名、remoteproc 节点和 IPI 配置。

先冻结 BSP、FreeRTOS 内核、工具、Linux 与 OpenAMP 的版本，确认本版本是否提供所需 CPU1 启动与通信路径。第一阶段只运行 RTOS 最小工程；第二阶段才加入 Linux 与核间通信。内存分区、向量、外设、GIC、时钟和共享缓冲各有明确归属。

49.2 移植五步：工程、异常、tick、内存、配置

  1. 选正确 port：核对所选源码树；上游 GCC Cortex-A9 port 位于 portable/GCC/ARM_CA9。厂商 BSP 可能另有集成，不猜目录名。
  2. 核对异常入口：SVC/SWI 走移植层任务切换入口，IRQ 走该 port 的中断分发与返回路径；以 portASM.S 和链接向量为准。
  3. 建立 tick：由 BSP/port 的定时器配置提供，测量真实频率；不能只凭 CPU 主频假定分频关系。
  4. 核对内存：readelf -l 的各加载段、栈、堆、vring 与 Linux 保留区域不重叠；不是只比较一个起始地址。
  5. 配置与断言：按该版本配置优先级、tick、栈检查、静态分配与 FPU 使用；保留 configASSERT 验证集成。

不要创建 portUSE_PS_TIMER? 这类不存在的宏。复制配置前，必须在所用版本源码中找到宏的定义与消费位置。

49.3 先做能量化的 1 ms 周期任务

以下是任务函数片段，board_control_step 是你提供的业务函数；工程还需经验证的 BSP、向量、定时器、任务创建与 FreeRTOSConfig.h。

C
static void control_task(void *argument)
{
    const TickType_t period = pdMS_TO_TICKS(1);
    TickType_t last_wake = xTaskGetTickCount();
    (void) argument;
    configASSERT(period > 0);
    for (;;) {
        board_control_step();     /* 有界、无阻塞 IO，需由本工程实现 */
        vTaskDelayUntil(&last_wake, period);
    }
}

在 configTICK_RATE_HZ=1000 时，每 tick 为 1 ms。绝对延时避免把每轮执行耗时不断累加为漂移，仍不保证任务准时运行或在截止期前完成。用下方周期实验先算量化，再上板量唤醒与执行时间。

49.4 任务划分与所有权

控制任务高优先级且工作量有界；通信与日志在较低优先级任务执行。控制数据采用不可变快照或清楚的交接协议；大块数据传指针时要说明谁分配、谁持有、何时归还。

速率单调（RM）按周期排序，截止期单调（DM）按相对截止期排序；二者不能混为一句“截止期最紧就是 RM”。经典利用率界依赖独立周期任务、可抢占及截止期等于周期等假设，有共享资源时须计阻塞时间。

task notification、队列、互斥量和事件组按通信与同步语义选择；速度数字必须绑定版本、处理器和测量条件，不能当作通用保证。

49.5 调试：tick、栈、时间线与 A9 异常

  • tick：用独立时间基准与 GPIO/定时器交叉验证，记录配置和测量区间。
  • 栈与运行统计：按当前 API 读取栈高水位，确认返回单位为 StackType_t 项或该版本定义的单位；运行统计计时器要独立、足够精确并考虑回绕。格式化输出本身有开销。
  • 时间线：记录任务释放、开始、结束、阻塞和 IRQ，区分 tick 量化、唤醒延迟与业务执行超时。
  • A9 异常：Data Abort 收集 DFSR/DFAR，Prefetch Abort 收集 IFSR/IFAR；同时保存异常模式、SPSR、LR 与必要寄存器。PC 还原偏移按异常类型和指令状态核对。

Cortex-M 的 HardFault、SCB_CFSR、SCB_AIRCR 和自动堆栈 xPSR 模型不适用于 Cortex-A9。

49.6 用现象区分配置与业务故障

现象先取什么证据
调度器启动后无任务日志首任务入口、SVC 向量、栈/堆与断言位置
任务只运行一次tick 是否增加，延时列表是否到期，IRQ 是否到达本核
FromISR 后随机错误实际 GIC 优先级、port 门槛、嵌套与 API 是否允许在 ISR 使用
周期越来越慢相对延时、任务执行时间、超时及优先级干扰
通信不通共享地址、通知机制、端点发现、驱动与缓冲所有权
Abort异常状态、故障地址、匹配 ELF 的反汇编和栈范围

异常名称与寄存器属于架构知识，不能把所有崩溃统一叫 HardFault。

49.7 动手实验：从 1 ms 到 100 µs

问题：1 kHz tick 能否用 vTaskDelayUntil 表达 100 µs？不能：一个 tick 已是 1000 µs。提高 tick 频率还会增加中断与调度开销，不能只改常量就宣布满足要求。

动手实验 L49-1：独立测量释放、唤醒与完成
  1. 先完成 1 ms tick 周期任务，记录 GPIO 边沿与执行时间。
  2. 再用硬件定时器或 PL 产生 100 µs 事件；ISR 只做有界工作或通知任务，明确事件积压时的处理策略。
  3. 统计事件时刻→ISR、ISR→任务开始、任务执行三段延迟；加入日志/通信压力。
  4. 比较裸机、RTOS 两个版本的 max/p99 和超时计数，记录采样条件；不能用页面模型代替上板数据。

49.8 移植检查清单

  1. 核对 A9 异常向量与 port handler 的符号地址。
  2. 独立测量 tick，中断确实送到目标核。
  3. 加载段、栈、堆和共享缓冲不重叠。
  4. configASSERT 与栈检查能被受控测试触发。
  5. FPU/NEON 使用规则与所选 port、ABI 一致。
  6. 通信先 echo，再业务；重启、断连与缓冲耗尽均有恢复策略。

每项留存命令或波形，而不只打勾。

49.9 GIC 优先级：逻辑值与寄存器编码

数值越小，GIC 中断优先级越高。Zynq-7000 实现的有效优先级位需按 UG585 与 port 配置核对。若配置 32 个级别，则逻辑值 p 写入 8 位优先级寄存器时通常为 p << 3。

TEXT
例：32 个有效级别时
逻辑优先级  5 → 寄存器值 0x28
逻辑优先级 20 → 寄存器值 0xA0
0xA0 不是逻辑优先级 5。
上游 ARM_CA9 的 configMAX_API_CALL_INTERRUPT_PRIORITY 按 port 期望的逻辑值配置。
逻辑值越小、越高于允许 API 的门槛者，不得调用内核 API；
门槛边界是否允许及保留级别，按该版本 port.c/portmacro.h 的断言与注释核对。

先在实际源码中确认逻辑值与位移的处理，避免重复移位。不要从 Cortex-M 配置中直接复制已左移的优先级常量。

49.10 静态分配使内存预算可见

使用 xTaskCreateStatic 需要开启静态分配配置，并提供持久存在的 StaticTask_t 与 StackType_t 数组。栈深度参数以 StackType_t 项计，不直接等同于字节。还需按配置为 Idle/Timer 服务任务提供静态资源。

静态分配减少运行时分配的不确定性，不等于整体时间行为完全确定，也不构成 SIL 认证结论。仍要验证栈深度、阻塞、IRQ、外设与共享总线干扰。

49.11 核间通信：先选实现，再对照 API

OpenAMP 与 rpmsg-lite 是不同实现。先选能覆盖所用 Zynq-7000/BSP 版本的参考工程，再按它的初始化、资源描述、端点发现与缓冲释放约定集成；不能混写两个库的 init/create/send API。

  1. 核对固件加载方式与 Linux 驱动，不假设必然生成 /dev/rpmsg0；字符设备是否出现取决于绑定驱动与版本。
  2. 固定共享内存、vring、缓存属性与通知机制。
  3. 先跑官方 echo，记录端点地址与发现过程。
  4. 明确零拷贝接收缓冲是自动归还还是由应用保留后释放，避免重复释放。
  5. 加入 seq、超时、重启代次与流控，再接入控制协议。

49.12 A9 故障黑匣子：先捕获，再发布有效记录

异常入口通常需要汇编胶水保存现场。以下是设计记录格式的流程，不是可直接复制的异常 handler；捕获寄存器与异常返回依赖具体 A9 port。

TEXT
记录区域：由链接脚本与 Linux 保留内存共同约定，固定大小和版本。
记录内容：记录版本、异常类型、CPU/模式、SPSR、原始 LR、故障寄存器、
          保存的通用寄存器、任务 ID、栈范围、序号、校验。
捕获顺序：使记录无效 → 保存现场 → 计算校验 → 完成必要的缓存/屏障
          → 最后发布有效标记 → 按本板恢复策略处理。
重启读取：先验证版本、长度与校验；用相同 Build ID 的 ELF 解码。
OCM/DDR 在复位后的保留性需按复位种类、启动软件和硬件实测确认。

不要在 A9 handler 中写 SCB_AIRCR；不要保存复位后可能无效的任务名指针。需要名称时复制有限长内容或保存稳定 ID。
