46.1可用性的算术基础

指标定义示例
MTBF平均无故障工作时间电源 MTBF=50 万小时 → 年失效率 ≈1.75%
MTTR平均修复时间备件在库 2h / 需等货 72h 差 36 倍
可用度 AA = MTBF/(MTBF+MTTR)四个9(99.99%) = 年停机 ≤52 分钟；五个九 ≤5.3 分钟

冗余的本质：用并联结构把 MTTR 从「等维修」变成「瞬时切换」，同时多通道降失效概率。但冗余引入新失效模式（共因/切换失败）—— 设计目标是系统级最优而非堆料。

46.2冗余分类学与切换模式

  • 按层次：元件级(双电容/双MCU互检) → 模块级(双电源/双网卡) → 设备级(CPU 双机热备) → 网络级(环网/双网) → 系统级(异地容灾)；
  • 按热备程度：冷备(上电加载需分钟级)/温备(已运行但不接负载)/热备(实时同步，无扰接管)——工业控制只接受热备；
  • 1:1 与 N:1：关键控制器 1:1 专备；大量同型 IO 模块可 N:1 共享冷备池 + 热插拔。

46.3控制器（CPU）冗余 ★核心

① 工作机制（以主流 PLC 冗余为例）

TEXT
        ┌─── 同步链路(光纤/背板, ≥100Mbps) ───┐
   ┌────┴────┐                          ┌─────┴───┐
   │ 主站 R0  │  周期性状态镜像：         │ 备站 R1  │
   │ 执行程序 │  · 输入映像/中间变量      │ 只同步   │
   │ 输出刷新 │  · 定时器/计数器当前值    │ 不输出   │
   └────┬────┘  · 报文缓冲              └─────┬───┘
        ├──────────┐     ┌──────────────────┘
   IO网络A│      IO网络B(双网接入同一IO)
        ▼          ▼
   [现场设备] ← 输出仅由主站驱动，切换瞬间无扰动

检测→主失联/自检失败→备站完成最后一次同步校验→接管输出→上报HMI(全程<300ms典型)

② 关键技术点

  • 同步内容分层：周期数据(IO映像/DB变量)每扫描镜像一次；事件数据(报警/SOE)即时推送；程序与组态版本一致性校验（不一致禁止冗余）；
  • 无扰切换条件：定时器剩余值、积分器状态、步序号都必须同步 —— 否则切换后逻辑「跳变」。这正是你 PLC 项目里功能块槽表要进 RETAIN 区的原因（31章伏笔）；
  • 仲裁与脑裂：两台都认为对方死了怎么办？→ 第三方仲裁（独立心跳通道/仲裁服务器/IO 层硬件互锁「只有持有使能继电器的一方允许输出」）。软件仲裁必须叠加硬件级输出互斥才是工业级答案；
  • 回切策略：自动回切可能引发振荡（反复切换），工程惯例是手动确认回切。

46.4IO 层与传感器层冗余

  • 双路接入：关键 DI/AI 同时进主备两个控制器的独立 IO 模块（含独立供电保险）；
  • 传感器 2oo3 表决：三个独立测量点，软件取中值输出，单点漂移被自动屏蔽（呼应44章 SFF/CCF）—— 安全系统的标配；
  • 执行机构冗余：调节阀带手动旁路 + 切断阀串联的双阀门策略（机械冗余兜底）。

46.5电源冗余（最便宜也最容易被忽视）

  • 二极管/ MOS 解耦冗余模块：两台 24V 电源经解耦器并联储电，单台损坏零中断（如西门子 SITOP RED 系列）；
  • 上游双回路市电 + ATS 自动切换；关键负荷加 DC-UPS（缓冲模块+电池），撑过切换间隙 10s~min 级；
  • 纪律：冗余路径上的任何单点（螺栓/端子/断路器）都要审视——见过太多「双电源共用一个空开」的假冗余。

46.6网络冗余四方案对比 ★（面试高频）

方案标准拓扑切换时间节点要求成本
RSTP 快速生成树802.1w任意(阻塞口)1~10s 级普通交换机低
MRP 介质冗余IEC 62439-2环型(MRM定管理站)200ms 保证 / 30ms / 10ms(MRPD)支持 MRP 的交换机中
PRP 并行冗余IEC 62439-3双独立全网(同时收发)0ms 无缝DANP 双口节点 或 RedBox 接入普通设备高(双网设施)
HSR 高可用无缝环IEC 62439-3环型，帧双向环流0ms 无缝每节点 HSR 硬件转发行口中高
  • 选型直觉：能容忍亚秒级中断的过程监控 → MRP 环网（性价比之王）；运动控制/保护类零容忍 → PRP/HSR（电力行业变电站标配 PRP）；办公融合网才考虑 RSTP 兜底；
  • PRP 的 RedBox 让普通单口设备「假装」双口节点 —— 改造存量系统的关键武器；
  • 实践补充：交换机级联不要超过厂商建议跳数、组播流量开启 IGMP Snooping（否则泛洪拖垮 CPU，47章案例）。

46.7软件层高可用（你的项目现在就能做）

  • 进程守护 + 三级看门狗（34章已实现）；
  • 配置/程序双分区 + 校验回滚（升级不中断思路）；
  • Modbus/Web 服务多实例绑定不同端口，前端自动 failover；
  • 把 46.3 的「主备心跳+硬件输出互锁」做成两块开发板实验 —— 见 L46-1。

常见问题 FAQ（避坑指南）

Q1：什么叫「脑裂」？工业上怎么根治？

双主并存：两台控制器都抢输出 → 设备乱动。根治靠输出通路物理互斥（仲裁继电器/PL 层互锁），软件仲裁只能减少概率不能消除后果。任何冗余方案评审必问：「最坏情况两台同时认为自己是主，现场会发生什么？」

Q2：PRP 为什么比 MRP 贵这么多？

PRP 要求节点双网口同时收发并在接收端按序列号去重（LRE 链路冗余实体），通常由 FPGA/专用芯片实现（HAT 硬件）；且基础设施要建两张平行网络。MRP 只是环上一条备份链路的通断管理，普通工业交换机即可。

Q3：冗余系统怎么验收测试？

故障注入矩阵全覆盖：拔主 CPU/拔同步线/拔 A 网/拔 B 网/双网同拔/主备电源各拔/仲裁链路断/恢复顺序组合……每项记录切换时间与过程量扰动曲线。没有这张表就不算交付了冗余系统（对照35章方法论的扩展版）。

🧪 动手实验 L46-1：迷你双机热备

两块领航者（或一块板双核 AMP 模拟）：① 主备心跳走以太网 UDP（20ms 周期+序号）；② 输出互锁：各自用一个 GPIO 控制「输出使能」继电器逻辑，只有持令者置位；③ 心跳丢失 3 周期即切换，LED 显示角色；④ 注入测试：拔线/杀进程/双向同时启动，记录切换时间与是否出现双主。这个实验做完，「冗余」对你不再是 PPT 名词。

46.9深潜：主备数据一致性协议（简化两阶段）

  1. 稳态镜像：主站每扫描周期把 {IO映像, FB槽表, 步序, 定时器剩余} 打包+序号 seq 发备站；备站 ACK 最近连续 seq；
  2. 切换窗口：备站只允许在「收到完整偶数? 对齐的周期包」后才具备接管资格 —— 避免半包状态上线；
  3. 事件通道：报警/操作日志走独立即时通道不进周期镜像，防大事件拖慢扫描同步。
