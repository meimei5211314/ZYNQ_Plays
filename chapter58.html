实时需求先写成时间契约

周期T表示任务多久释放一次，截止期D表示每次释放后必须多快完成，执行时间C表示占用CPU的计算需求，响应时间R包含等待、抢占和执行。C=0.8 ms不代表R=0.8 ms；一次平均延迟50 μs也无法证明所有请求在1 ms内完成。端到端链路还包含采样相位、DMA等待、IRQ唤醒、线程处理及输出同步，不能只测中间函数。

先写明截止期从哪个物理或软件事件开始，到哪个可观察事件结束，超期怎么处置。控制任务宁可丢弃过期命令还是必须处理全部历史？周期错过后追赶多次运行还是跳到下个绝对时刻？使用绝对时间周期可避免相对sleep逐步累积漂移，但不能消除调度延迟。选择时钟源、时间戳位置和测量误差要一致记录，尤其是PS时间与PL计数器还需有跨时钟关联方法。

PREEMPT_RT改变可抢占性，不创造算力

PREEMPT_RT使大量内核路径变得可抢占，将许多中断工作线程化，并改变部分锁的实现以支持优先级继承。这有助于降低高优先级任务就绪后的等待，但仍存在底层不可抢占区、raw锁、总线争用和固件等影响。它不会让一个CPU上总计算需求超过100%的任务集全部按期完成，也不会替驱动保证每个临界区都有上界。

课程2020.2系统不能照着当前主线文档勾一个选项就认为完成RT迁移；应核对实际内核基线、对应RT补丁、架构支持、配置和驱动兼容性。设置SCHED_FIFO还需分析同优先级关系、IRQ线程优先级、亲和性及内核实时带宽配置。一个忙等的高优先级用户线程可能饿死它依赖的低优先级IRQ线程。内存锁定、预触页和固定分配能减少某些不确定性，但每项都应与测量目标对应。

先声明分析模型

本章算例采用一个CPU、可抢占固定优先级、周期或最小间隔任务、无释放抖动、无自挂起、D≤T，并假设执行需求与阻塞上界已可靠给定。按优先级从高到低，响应时间迭代为Rᵢ⁽ᵏ⁺¹⁾=Cᵢ+Bᵢ+Σ⌈Rᵢ⁽ᵏ⁾/Tⱼ⌉Cⱼ，求和遍历更高优先级任务。初始化Rᵢ⁽⁰⁾=Cᵢ+Bᵢ；若稳定且不超过Dᵢ则在这些假设下通过。

B包含经过锁协议分析的低优先级阻塞等有界因素，不能凭一次测量取最小值。IRQ、调度和上下文切换开销也不能漏掉；可明确计入C、额外干扰任务或适用的开销模型，避免重复计入。释放抖动、DMA自挂起、跨核共享锁及分区迁移出现后，这个简单递推不再足够，必须扩展模型。教学交互仅计算所输入模型的不动点，不测真实WCET，也不会自动发现遗漏任务。

完整手算一个不动点

三项周期任务优先级依次降低：(C,T,D)分别为(1,4,4)、(1.5,5,5)、(2,10,10)，单位ms。另有低优先级维护工作，其锁协议已给出第三任务阻塞上界B₃=0.5 ms；这里只分析第三任务。起点R₃=2.5。第一轮2.5+⌈2.5/4⌉×1+⌈2.5/5⌉×1.5=5；下一轮为6；再下一轮为7.5，之后保持7.5，因此R₃≤10。

R0 = 2.5
R1 = 2.5 + 1*1 + 1*1.5 = 5
R2 = 2.5 + 2*1 + 1*1.5 = 6
R3 = 2.5 + 2*1 + 2*1.5 = 7.5
R4 = 2.5 + 2*1 + 2*1.5 = 7.5

三项利用率之和为1/4+1.5/5+2/10=0.75，只描述CPU需求比例，未包含该维护工作的完整负载或阻塞，不能仅凭0.75宣称系统可调度。所有任务都需独立检查，尤其第一、第二任务自己的阻塞也要有上界。这个算例展示的是在明确条件下如何给第三任务求界，而不是实测Zynq性能。

小改动可以跨过截止期

保持前述C与T，若第三任务阻塞升为3 ms，起点变5。迭代得到8.5，再得到11，已经超过D=10，于是该模型不能证明满足截止期。平均CPU利用率几乎不变，长临界区却足以破坏时限。只调整线程优先级可能把问题转移给另一个任务，必须重新分析全部受影响任务。

优先级反转场景中，低优先级持锁者阻塞高优先级，中优先级又抢占持锁者；优先级继承可以限制这类额外干扰，但不缩短持锁者本身不可预测的I/O。不要在共享锁内做无上界设备等待、文件写入或大量日志。把资源获取提前、把临界区缩到有界复制、用消息转交拥有者，往往比继续提高优先级更有效。对每个优化重新记录C、B、释放模式与依赖，才能证明它改善的是哪一项。

WCET证据不能由一个最大值冒充

WCET是给定硬件与执行条件下的最坏执行时间界；有限测量得到的是观察到的最大值，不能自动当严格上界。A9缓存、分支预测、DDR竞争、中断和频率状态会改变时间。测量需列输入边界、冷/热缓存、CPU/IRQ亲和性、频率、电源策略与其他总线主设备负载，解释哪些最坏情况已覆盖、哪些未覆盖以及采用了什么工程裕量。

cyclictest适合测周期唤醒延迟，却没有执行你的完整控制算法或验证DMA链路。先用它建立调度基线，再给真实任务加低干扰时间戳，比较唤醒到开始、开始到结束、物理事件到输出三个区间。配合调度/IRQ跟踪定位长尾，避免在高频实时路径中printf。压力试验同时考虑CPU、内存和I/O干扰，保留直方图、最大值对应的事件轨迹和截止期错失计数，而非只给一张平均值表。

把分析与测量组成可复核验收

响应时间交互采用单个高优先级干扰任务，便于逐轮观察ceil的阶跃；多任务手算中的求和需在纸面或自己的脚本扩展。用C=2、B=0.5、较高任务C=1和T=4，可得2.5→3.5→3.5 ms；然后另行核对前述多任务7.5 ms算例。若真实响应超过分析界，先查遗漏的阻塞、IRQ、抖动或自挂起，不能任意调参数后声称验证。

验收包包含任务表、优先级和亲和性、C/B来源、逐轮计算、内核/RT版本、实验配置、压力条件、错期策略与测量限制。没有板卡时可以完成数学分析和离线交互，但应明确未验证实际延迟。面向更复杂的多核流水线，可先固定任务分区，分别分析各核，再审计跨核资源和消息等待；若采用全局迁移调度，应选择适用理论。将假设写清楚，是实时论证可信度的一部分。

工程任务 · 为采样、处理、上报三任务建立固定优先级模型，输出逐轮响应时间和目标测量计划。

先用单HP任务交互验证2.5→3.5→3.5 ms，再独立核对多任务求和；具备RT内核时测cyclictest基线与真实端到端分布。

故障练习：加入一个低优先级长临界区或把IRQ线程优先级放到忙等线程之下，定位增加的是阻塞还是依赖等待。

验收：每个C/B与开销都有来源和范围；全部任务分别通过分析；测量没有未解释的超界；不将有限样本最大值直接称WCET。
