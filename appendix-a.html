A1 数字电路基础

Q1 什么是建立时间与保持时间？违例了会怎样？

【考察点】时序检查物理意义。
【要点】建立时间 = 时钟沿前数据必须已稳定的最小时长；保持时间 = 沿后需继续稳定的最小时长。建立违例可通过降频修复（周期拉长）；保持违例与频率无关，只能改布线/插延迟，芯片直接报废级。亚稳态是两者共同风险后果。

Q2 亚稳态是什么？工程上如何对付？

【考察点】CDC 意识（对应第22章）。
【要点】采样窗口内数据翻转 → 触发器进入非确定电平且恢复时间不定。对策：跨域两级同步器、握手、异步 FIFO、格雷码计数器；MTBF 公式说明「降低频率/提高器件速度只是缓解不是消除」。

Q3 经典题：异步 FIFO 最小深度计算（写100MHz突发120个，读80MHz每拍读1个）

【要点】最坏情形：写侧背靠背两个突发共 240 写入期间，读侧同窗最多搬 240×(80/100)=192 个 → 余量 240−192=48，深度取 48（常加余量到 64）。答题先写公式再代数，展示思路而非凑答案。

Q4 同步复位与异步复位的优缺点？你的选择？

【要点】同步复位：无亚稳态注入、但需要时钟活着、占数据路径逻辑；异步复位：立即生效不依赖时钟、但释放时刻可能违反恢复/移除时间 → 工业标准做法异步声明同步释放（两拍同步复位树），本课程代码即此风格。

Q5 竞争与冒险是什么？如何消除？

【要点】信号经不同路径到达同一门存在时差（竞争），可能产生毛刺（冒险）。消除：格雷码计数器、寄存器输出割断组合毛刺传播、卡诺图加冗余项、避免组合逻辑直接做时钟/复位。

Q6 为什么不建议门控时钟？正确做法？

【要点】组合逻辑门控会产生毛刺时钟导致随机误触发，且破坏时钟树平衡。正确：用使能时钟（clock enable 打拍）或厂商 BUFGCE 类专用原语。

Q7 组合逻辑里什么情况会综合出 latch？

【要点】if/case 分支未覆盖全部路径且未给默认值 → 需要「记住旧值」。后果：时序不可控、DFT 困难。修复：always @(*) 开头赋默认值 + case 补 default。

Q8 时钟偏斜(skew)与时钟抖动(jitter)的区别？

【要点】skew 是空间概念：同时钟到达不同寄存器的时间差（影响 hold/setup 预算分配）；jitter 是时间概念：同一节点时钟沿的周期间波动（吃掉 setup 裕量）。

A2 Verilog 语言与编码

Q9 阻塞与非阻塞赋值的本质区别？

【考察点】仿真调度语义。
【要点】阻塞=立即执行（顺序语义，描述组合逻辑）；非阻塞=统一排在当前时刻末尾更新（描述同步并行翻转）。铁律：时序 always 用 <=，组合 always 用 =。追问「交换 a,b」例子最能暴露理解。

Q10 reg 和 wire 的真正区别？reg 一定是触发器吗？

【要点】wire 是连续驱动的网络（assign/模块输出）；reg 是过程赋值变量。reg 在时序 always 中综合为 FF，在电平敏感 always 中综合为组合逻辑 —— 「数据类型≠硬件资源」。

Q11 三段式状态机的优点？Mealy 与 Moore 如何选择？

【要点】三段式：寄存器输出无毛刺、次态组合独立便于约束、可读性/可维护性佳。Moore 输出仅依赖状态（稳定、延迟一拍）；Mealy 响应快一拍但可能带输入毛刺 —— 安全相关逻辑优先 Moore。

Q12 generate for 与普通 for 的区别？

【要点】普通 for 在 always 内是时间上循环执行（仿真语义/可展开的组合复制）；generate for 是编译期展开生成硬件实例（模块/always 批量例化）。位宽参数化批量结构必用后者。

Q13 哪些语法不可综合？initial 完全不能用吗？

【要点】延时控制、fork/join、wait、文件 IO、动态类型等不可综合。例外：FPGA 支持 initial 对 reg 做上电初值（映射到配置存储器初值），测试平台随意用。

A3 ZYNQ / SoC 专项（高频！）

Q14 完整叙述 ZYNQ 从上电到 Linux 登录界面的流程。

【考察点】体系结构总纲（对应第12章）。
【要点】BootROM 采样 BOOT_MODE → 从介质读 boot.bin 头部 → 加载 FSBL 到 OCM → FSBL 执行 ps7_init（PLL/DDR/MIO）→ PCAP 配置 PL bitstream → 加载 U-Boot 到 DDR 并跳转 → U-Boot 按 bootcmd 取 zImage+dtb → 内核解压、解析设备树、驱动 initcall、挂 rootfs → init/inittab → getty 登录。能画出五级火箭图并说出每级交接物即为满分。

Q15 M_AXI_GP、S_AXI_HP、S_AXI_ACP 三者的区别与应用场景？

【要点】GP：PS 主→PL 从，32b，配寄存器（低带宽）；HP×4：PL 主→DDR 控制器直连端口，64b 高吞吐（DMA/视频）；ACP：PL↔L2 Cache 一致性口，小数据低延迟可命中缓存。一句话：控制走 GP、大流量走 HP、要缓存一致性走 ACP。

Q16 为什么 FSBL 必须放在 OCM 运行？

【要点】此刻 DDR 未初始化不可用，唯一 RAM 是 OCM；BootROM 的搬运目标也固定 OCM。FSBL 在 OCM 里完成 DDR 初始化后才具备搬运大镜像能力。

Q17 PL 的 bitstream 由谁、何时加载？有几种方式？

【要点】① BOOT.BIN 内嵌 .bit，FSBL 经 DevC/PCAP 加载（产品标准）；② JTAG 直接下载（调试）；③ 系统运行后由 fpga manager/devcfg 驱动加载（支持不停机升级逻辑）。追问点：PCAP 全称 Programmable Configuration Access Port。

Q18 AMP 场景下核1 是怎么被启动的？和 SMP 有何不同？

【要点】上电仅核0 执行；SMP 由内核启动后期唤醒核1 跑同一内核；AMP 则由 Linux 的 remoteproc 把核1 固件 ELF 写入保留内存并写 SLCR/唤醒寄存器跳转，核1 运行裸机/RTOS，经 OpenAMP/rpmsg 通信（对应第40章）。

Q19 IRQ_F2P 有多少根？设备树里怎么写第0根？

【要点】16 根，映射 GIC ID 61~68、84~91。DT 写法 interrupts = <0 29 4>：SPI 类型、号=GIC−32=29、上升沿触发。追问 GIC 三类中断（SGI/PPI/SPI）分布。

Q20 OCM 和 DDR 各适合放什么？

【要点】OCM 256KB 片上 SRAM，访问延迟依赖端口与仲裁：FSBL、异常向量表、热代码/实时数据；DDR 大容量但有控制器排队延迟：内核、应用、帧缓冲。追问 OCM 两种映射（低地址别名/高端 FFFC0000）。

Q21 MIO 和 EMIO 的区别？各举一个必须用对方的场景。

【要点】MIO：54 根 PS 专属引脚，不经 PL；EMIO：PS GPIO 经 PL 管脚引出（54 起）。场景：引脚物理位置在 PL bank 必须 EMIO；掉电/启动早期就要用的信号（如启动模式检测）尽量 MIO——PL 未加载时 EMIO 不通。

Q22 XADC 能做什么？PLC 项目里你怎么用它？

【要点】双 12bit 1MSPS，监测片内电压温度 + 外部模拟通道（VAUX）。课程用法：电位器→VAUX→IIO 子系统 in_voltage_raw 读数标定成 AI 通道；高速需求则 PL 经 DRP 直采+DMA（第38章延伸）。

Q23 为什么选 ZYNQ 而不是「MCU+FPGA」或纯 FPGA？（开放压轴题）

【答题框架】维度对比：带宽（片内 AXI vs 板间接口）、延迟（纳秒 vs 微秒）、功耗体积 BOM、开发效率（Linux 生态复用）、实时性架构（PL 补 OS 短板）。收尾落到具体项目证据（如 PLC：IO 引擎在 PL、业务在 PS）。切忌只背口号。

A4 工业总线 / PLC / 功能安全专项（10 题）★研发岗加分区

Q24 Modbus RTU 为什么要求帧间静默 ≥3.5 字符？违反会怎样？

【考察点】协议状态机与物理层耦合。
【要点】RTU 无长度字段，靠静默间隔定界；两帧粘连会被当单帧 CRC 校验失败。工程细节：高速率下 3.5 字符窗口极短（115200≈300μs），中断延迟大的系统要用 DMA 空闲中断(IDLE)而非逐字节计时判断帧尾。

Q25 4~20mA 相比 0~10V 的三个本质优势？

【要点】①电流源抗长线压降/线路电阻；②活零点断线自诊断(<3.6mA)；③恒流回路天然抑制共模干扰。追问：为什么上限选 20mA？（安全限值下功率预算与历史仪表兼容）

Q26 EtherCAT 从站为什么能用普通网卡做主站？从站却不行？

【要点】主站只管发标准以太网帧（SOEM 用户态即可）；从站必须在线旁路处理——帧经过时硬件级读写转发，普通 MAC 做不到，需要 ESC 专用芯片/FPGA 逻辑。「主简单从特殊」是它生态爆发的关键设计。

Q27 SIL2 系统允许用单通道 CPU 吗？条件是什么？

【要点】可以但苛刻：61508 表格按 SFF 分列——高 SFF(≥90%)时 HFT=0 允许 SIL2。前提是诊断覆盖到位（看门狗/RAM 测试/IO 回读/时钟监测）且证明 λDU 足够低。答出「结构约束与 PFD 计算双门槛」即专业。

Q28 双机热备的「脑裂」如何根治？只靠软件心跳行吗？

【要点】软件仲裁只能降概率；根治靠输出通路物理互斥（仲裁继电器/PL 层使能互锁），保证任意时刻只有一个控制器物理上能驱动负载。46章 L46-1 即其教学版。

Q29 CAN 节点反复进入 bus-off，标准恢复流程是什么？你会怎么改代码？

【要点】TEC>255 → bus-off；恢复需检测 128×11 连续隐性位。代码层：立即重入会风暴——指数退避 + 记录错误计数曲线定位根因（波特率采样点/线缆/地电位三查，45章 Q2）。

Q30 PID 积分饱和是什么？给出两种抗饱和策略。

【要点】执行器限幅期间积分持续累积 → 反向调节迟钝。策略：①钳位式(clamping)——输出限幅同时冻结积分；②反计算(back-calculation)——用实际输出与未限幅值之差反馈修正积分。工业库默认 clamping。

Q31 MRP 环网切换时间规格有哪些档？你的应用怎么选？

【要点】IEC 62439-2 定义 200ms(基础)/30ms? 常见实现 500ms/200ms/30ms 及增强 MRPD ~10ms? 工程口径：200ms 档够过程监控；伺服类选 ≤30ms 并核对驱动器通信超时参数（47章案例4的教训）。答题带数字才可信。

Q32 安全 PLC 与普通 PLC 的三大区别？

【要点】①硬件：冗余/多样性结构+高诊断覆盖率电路（认证过的看门狗、存储器测试）；②软件：受限开发流程（认证工具链、受限语言子集如 FBD only）、变更受控；③证据链：全生命周期文档+SIL 验证报告（TÜV 标志）。价格差 3~10 倍买的是「可证明」。

Q33 SOE 事件顺序记录对时钟精度的要求？如何达成跨装置排序？

【要点】典型要求 ≤1ms（继保场景更高）；达成路径：装置间 PTP/gPTP 亚毫秒同步 + 采集点硬件时标（在 IO 层打戳而非软件上报时刻）。反例即 47 章案例 9 的 800ms 惨案。

50.8深潜：CAmkES 完整 Hello（接口+组件+装配）

    int echo(in int x);                       /* 方法定义=IDL */
}
component Server {
    provides IHello svc;
}
component Client {
    control;                                  /* 有main入口 */
    uses IHello svc;
}
assembly { composition {
    component Server s; component Client c;
    connection seL4RPC conn(from c.svc, to s.svc);
} configuration { /* 可注入 int 参数/设置优先级 */ } }

/* client.c: #include   int run(void){ return svc_echo(42); }

50.9深潜：调试与验证手段清单

  • 内核调试输出：KernelDebugBuild 配置下 printk 级日志（性能损失大，仅调试版）；
  • sel4test：跑分套件全绿 = 移植基本可信；新增平台先过它；
  • 用户态 fault：IPC 报错码（seL4_InvalidArgument 等）逐位排查 cap 是否缺失 —— 「权限不足」是最常见新手错误，报错语义精确反而好查；
  • 形式化证明查询：Isabelle/HOL 规格在 l4v 仓库，可检索某 syscall 的证明引理 —— 不改证明也能读结论。

⑤ 与 Linux 共存：camkes-arm-vm 路线

  • 动机：保留 Linux 生态(Modbus/Web)同时用 SeL4 圈住安全组件；
  • 形态：CAmkES 声明 VM 组件（含 Linux 镜像/DTS 资源描述），seL4 以 hypervisor 模式跑 guest；原生安全组件与 VM 经跨虚拟机通信组件(camkes-vm-cross-vm)交换数据；
  • ZYNQ 内存划分示例：Linux guest 512MB @0x10000000 / 原生组件 64MB / seL4+capdl loader 低段 —— 与 40 章 AMP 划分思想同源，只是"第二系统"从裸机升级为受隔离的完整 OS；
  • 成本提醒：VM 路线构建复杂度陡增，建议先跑通纯原生双组件再上 VM。

⑥ 常见坑与验收

  • 无日志 → UART 口/波特率配置（③表第一行）；
  • 启动即 fault → 固件加载地址与链接脚本不符（capdl loader 对地址敏感）；
  • 组件间通信超时 → endpoint 连接方向声明反了 / cap 未授予（看生成文件 camkes.gen.capdl 里的 cap 表）；
  • 验收标准：sel4test 在板上全绿 + 自定义双组件（echo 组件）经 endpoint 往返 1000 次零失败，并导出一份 camkes.gen.capdl 标注每个 cap 的归属 —— 这份标注就是你对「最小权限」的具象化理解证明。
