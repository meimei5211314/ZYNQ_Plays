先问谁能写，再选原子操作

并发缺陷通常不是“同时执行得太快”，而是两个执行主体对同一个对象缺少合法的访问关系。C11中，冲突的非原子访问若没有适当同步，会构成数据竞争并导致未定义行为。某次板上运行恰好没撞上不能证明安全。先为每个共享字段指定写者、读者、发布时间和归还时间，再决定锁、消息或原子方案。

SPSC的前提是恰好一个生产者推进head、一个消费者推进tail。两个中断上下文都调用push，即使从未同时进入，也必须证明它们被同一种串行化机制保护，否则已超出此算法。payload可以是普通对象，只要发布前仅生产者写、取得所有权后仅消费者读、归还后才允许覆写。原子索引的作用是建立交接契约；并非要求把每个payload字节都改成原子。

release与acquire连起数据关系

生产者先写slot，再对head做release存储；消费者用acquire读取head，并观察到对应发布后，才能读取slot。消费者读完slot，对tail做release；生产者通过acquire观察到归还后，才能重新写该槽位。这是两个方向的交接。只给head加屏障而让tail随意访问，可能在槽位复用时破坏安全。

/* C11消息发布示意片段；payload仅在该协议保护下访问 */
payload = value;
atomic_store_explicit(&ready, 1, memory_order_release);
/* 另一个线程：观察到本次发布后才读取payload */
if (atomic_load_explicit(&ready, memory_order_acquire))
    consume(payload);

这段单次发布片段不是可无限复用的邮箱：ready何时清零、旧数据何时不再被读，都还没定义。relaxed仍提供该原子对象本身的原子性和修改顺序，但不独立发布旁边的普通数据。acquire必须通过观察相关release形成关系，两个地方各写一个屏障不会自动产生通信。

手算一个留空槽的环

选N=8，索引在0到7之间循环，next=(head+1)&7。head==tail表示空，next==tail表示满，因此可用容量是7而不是8。head=6、tail=2时，已有(6−2)&7=4个元素，可再放3个。生产者读取tail可能稍旧，最多保守地误判满；消费者读取head稍旧，最多保守地误判空。这种保守性成立于单写者和正确发布协议。

/* push的核心片段；省略结构体、初始化和完整错误路径 */
unsigned h = atomic_load_explicit(&q->head, memory_order_relaxed);
unsigned n = (h + 1u) & (N - 1u);
if (n == atomic_load_explicit(&q->tail, memory_order_acquire))
    return false;
q->slot[h] = value;
atomic_store_explicit(&q->head, n, memory_order_release);

自己的索引由自己唯一写入，因此可relaxed读取；对方索引承担交接，需要相应acquire。N必须为2的幂才能用掩码代替取模。若改用单调计数器和全部N个槽位，就必须重新证明回绕、差值范围与满空判定，不能混用两种设计的公式。

边界、退出与过载也是算法

队列满时选择返回失败、丢弃新样本、覆盖旧样本或阻塞，属于业务契约。留空槽SPSC不能在满时由生产者强行推进tail：那会让tail出现第二个写者，也可能覆写消费者正在读取的对象。需要覆盖策略时应另选经过证明的算法。固定容量只解决内存上界，无法替持续过载的系统创造吞吐量。

例如生产率100 k项/秒、消费率80 k项/秒，净积压20 k项/秒；可用容量1023从空到满大约51.15 ms。即使每次操作都无锁，也只是在这个时间后更快地报告满。退出时还需定义停止生产、排空或放弃、join消费者、销毁内存的顺序。消费者拿到的是槽位内指针时，归还tail之后不得继续使用该指针；否则生产者可以合法覆写它。

原子不保证处处无锁

_Atomic类型保证语言层面的原子操作，但具体目标宽度可能由库函数甚至锁实现。对目标编译器检查atomic_is_lock_free、生成指令及链接依赖，尤其是32位A9上的64位原子。不能在可能借助阻塞锁实现的原子上，未经分析就放入硬中断上下文。无锁只表达系统级进度性质，不等于每个参与者在固定步数内完成，也不等于实时截止期保证。

head与tail若落在同一缓存线，即使语言正确也可能频繁争夺缓存线。可以按目标缓存线规划索引存储，但填充大小需用目标布局验证，不能把桌面机64字节结论直接当A9事实。一次acquire/release的真实成本还依赖编译器、架构和共享状态。先用正确算法建立基线，再测吞吐和尾部延迟；不要通过删除同步来优化一个已经有数据竞争的程序。

先跑边界自检，再扩展并发压力

参考labs/c/spsc.c自带单线程交错自检：验证空读、填满、拒绝额外入队，以及10万项递增序号的保序与回绕，并输出atomic_is_lock_free。它不创建线程，没有pthread依赖，也不测真实并发。按构建说明创建labs/.build，再用gcc -std=c11 -O2 -Wall -Wextra -Werror -pedantic labs/c/spsc.c -o labs/.build/spsc_selftest构建并按平台运行。实现用显式回绕，支持非2次幂深度；掩码片段只是N=8的教学变体。

学习者扩展可用SPSC_NO_MAIN复用实现，另写生产/消费线程，增加派生校验、满/空计数、可复现延迟和退出同步，验证“成功入队数=成功出队数+占用”。这不属于现成自检。支持时单独使用TSan检查该线程扩展，不要与ASan混成同一构建。单线程通过不能证明弱内存并发安全，线程压力无告警也不能替代交接关系证明；目标A9的布局、原子实现与性能还需单独核对。

不要跨越模型适用范围

本章发布交互允许逐步安排“写payload、发布、观察、读取”的顺序，用于发现缺少交接的反例。它不执行C编译器、不模拟ARM弱内存模型，也不产生真实竞态概率。模型展示“可能错误”是一种解释；只有经过语言和架构契约推导，才能说明实际实现允许哪些观察。

用户态C11原子、Linux内核的smp_store_release/smp_load_acquire和设备DMA屏障属于不同接口体系。不能把stdatomic.h原样塞进内核，也不能对MMIO寄存器使用atomic_fetch_add来替代设备规定的读写。若环的一端变成PL DMA，CPU原子并不会替代DMA映射、缓存同步和设备所有权位。迁移前重新列出参与者和观察域，并注明哪个API建立CPU间关系、哪个API建立CPU与设备关系，避免看似相同的“发布”二字掩盖不同的硬件条件。

按labs/README.md构建运行单线程10万项自检，再用SPSC_DEPTH=3验证非2次幂回绕；并发压力需另写线程入口。

故障练习：在独立实验副本中把release/acquire换成relaxed，解释失去哪条happens-before关系；主机不复现时仍提交合法交错反例而非声称安全。

验收：自带自检空满/保序/回绕通过；每个索引仅一个写者且payload关系完整；线程扩展另验退出及总数守恒；明确目标原子是否无锁。
