时间值先注明来自哪只钟

墙上时间适合日志和跨重启标识，单调时间适合测量间隔和控制超时。系统校时或人工改时可能让实时时钟前跳或后退，用它比较“是否超时”会发生提前到期或永不到期。Linux 的单调时钟通常暂停于系统挂起；若需求包含休眠时间，应考虑相应的 boottime 语义。

原始硬件计数、经过频率校正的单调时间、PHC 和 UTC 不是可随意相减的同一域。定义一个时间戳结构至少包含数值、单位、时钟域、事件位置与有效性。对于“采样时刻”，注明是 ADC 触发、DMA 完成、中断入口还是用户线程读出；同样打印纳秒，也可能代表相隔很远的事件。

先编写时间契约：截止期按本机单调钟判断，操作日志记录墙钟并附启动 ID，跨设备对齐使用经验证的同步时间。重新启动后单调值重新计数，需要启动 ID 防止两次运行的数字被错误比较。对未知时钟域的数据应拒绝直接计算延迟，而不是默认它们已经同步。

回绕可算，但需要时间范围假设

32 位、每微秒加一的无符号计数器约 4294.967296 秒回绕一次，即约 71.58 分钟。开始值 0xfffffff0，结束值 0x00000020，在 32 位无符号模运算中差值为 48，而不是一个巨大的负数。前提是实际间隔小于一次完整回绕；如果中间已经多绕一圈，仅靠这两个读数无法知道。

uint32_t elapsed = (uint32_t)(now - start);
if (elapsed >= timeout_ticks) { /* expired */ }

以上是间隔计算示意，必须确保计数器宽度、类型与最大检查间隔匹配。对模空间中的先后排序还常要求差值小于半范围；不要把这种排序与无符号间隔公式混为一谈。若计数器由两次寄存器读取拼成 64 位，还应避免低字回绕时拼出不一致值。

测试时无需真的等七十分钟：从边界附近开始计数，覆盖回绕前、回绕时和回绕后。把超时阈值设到边界附近，再检查严格大于还是大于等于的定义。长时间稳定性问题往往可以用这种缩短计数范围的模型快速复现。

漂移与分辨率不是同一种误差

50 ppm 表示每百万时间单位误差约 50 个；在未校准且误差恒定的简化条件下，60 秒可积累 3 ms。两设备分别为 +50 ppm 与 −50 ppm，相对漂移可达 100 ppm。时钟显示一纳秒的分辨率并不说明它与真值只差一纳秒，振荡器、温度、同步残差和采样位置都影响准确度。

建立预算时分别列固定偏移、频率误差、量化、软件排队与链路不对称。若中断延迟在 5–40 μs 波动，用户态读取事件时间也会携带这类变化；不能用同一平均值给所有事件补偿。需要在尽量靠近事件的位置锁存计数，再把该硬件域映射到系统时间。

跨域映射可用成对观测拟合 t系统≈a×t硬件+b，并记录拟合窗口和残差。频率变化、休眠或计数复位后应重新判断映射有效性。下方时钟面板只核算计数差、理想漂移和路径不对称偏差；没有温漂、网络拥塞或真实同步伺服，因此不能产出板卡同步精度证书。

用四个时间戳推导 PTP 偏移

以主钟 A 和从钟 B 为例，A 发送为 t1，B 接收为 t2，B 发送回程为 t3，A 接收为 t4。在路径对称且交换期间频差可忽略时，偏移 θ=[(t2−t1)−(t4−t3)]/2，单程延迟 d=[(t2−t1)+(t4−t3)]/2。必须先统一时间单位和时间戳含义。

若 t1=0、t2=130、t3=230、t4=160 μs，则 θ=100 μs，d=30 μs。B 比 A 快 100 μs，扣掉偏移后双方时刻可以对齐。若真实正向 50 μs、反向 10 μs，按对称公式会额外产生 20 μs 偏移误差；多打印小数不会消除这项系统误差。

PTP 不只是发送四条数字，还需要实际 MAC/PHY/驱动的时间戳支持、时钟调节与网络条件。先查询平台和驱动能力，再选同步方案；不能把其他 Zynq 系列的 TSU 支持直接套到课程板。软件时间戳和硬件时间戳采集位置不同，比较时要明确是哪一种。

从时间戳到可验证的延迟

对一条采集链记录触发、入队、处理开始和发送完成时间。队内等待为处理开始减入队，端到端年龄为使用时刻减采样时刻。若采样钟与系统钟不同，先完成时钟映射，再计算年龄；未同步设备之间直接相减，得到的可能主要是偏移而非传输延迟。

Linux 网络时间戳由 socket 选项请求并通过附带消息等路径返回，具体能力取决于驱动。应检查返回标志、时间戳槽和错误状态，不能在硬件戳缺失时静默退回软件戳却保留原精度说明。对发送端还要明确“排队”“驱动交付”与“线上发出”的差别。

面板实验计算 16 位计数回绕后的间隔、ppm 累计漂移和不对称链路造成的偏移误差，不生成或校正事件顺序。阶段延迟与跨域校正需另用脚本或实际记录：先验证同域阶段之和，再引入偏移与漂移，保存原始时间戳、序号和校正参数。校时跳变和同步失锁也属于扩展故障；失锁后应扩大误差界或标记无效，不能继续宣称精确对齐。

为时钟失效设计可接受行为

关键控制应规定时间失效时如何行动：拒绝过期输入、缩小允许动作范围、切换本地模式或进入安全状态。记录同步状态变化和最后成功同步时刻，根据漂移上界估算当前不确定度。若允许误差 1 ms，残差为 0.2 ms，相对漂移上界 100 ppm，则最多约 8 秒后会用尽剩余预算。

这个 8 秒来自 (1−0.2)ms/100ppm，只有漂移上界可信时才有效。重连后也不能立即采用一次异常交换更新所有时间；应按所选同步实现的状态与过滤规则判断。产品策略要考虑时钟被错误配置或网络时延异常，不能只考虑正常启动。

验收提交时间域表、回绕向量、误差预算与失锁轨迹。每一条延迟报告都应能回答事件发生在哪里、读的是哪只钟、是否跨域以及误差多大。迁移到硬件后再用公共触发或合适仪器比较真实事件，主机计算只验证数学与软件边界，不能代替平台时间戳测量。

工程任务 · 完成含回绕、漂移和失锁处理的采集时间契约。
