47.1抓包工具箱与正确姿势

① 部署方式（交换机时代的关键）

方式做法适用
端口镜像 SPAN交换机把源端口流量复制到观察口：observe port 配置一条命令★ 首选；注意镜像口带宽是否够（万兆源→千兆口会丢包）
RSPAN跨交换机远程镜像（经 VLAN 承载）大型厂区集中监控
硬件 TAP串联分流入分析口（无源保真）需绝对无干扰的光纤/关键链路
板卡直抓你的 PLC 本机 tcpdump（自己既是端点）快速验证；看不到链路层他机流量

② 命令速查

BASH
# 板上抓取（写文件防内存爆）
tcpdump -i eth0 -w /tmp/mb.pcap 'port 502'
# Wireshark 显示过滤器（不是捕获过滤器！语法不同）
modbus                          # 所有 Modbus

# 统计利器：Statistics → Conversations / IO Graph（看突发）
# 大文件离线分析：tshark -r big.pcap -Y "modbus" -T fields -e frame.number ...

47.2Modbus TCP 帧逐字段解剖 ★

一次「读从站 1 的 MW0 起 2 个寄存器」的请求，以太网帧载荷十六进制：

TEXT
请求:  9c 4b 00 00 00 06 01 03 00 00 00 02
       ───── ──── ──── ── ── ──── ── ──── ────
        │     │    │   │  │   │   │   │    └ 数量 Quantity=0002 (Big-Endian!)
        │     │    │   │  │   │   │   └ 起始地址 Start Addr=0x0000 → %MW0
        │     │    │   │  │   │   └ 功能码 FC=03 Read Holding Registers
        │     │    │   │  │   └ 单元标识符 Unit ID=01 (从站地址)
        │     │    │   └──┘ 长度 Length=0x0006 (后续字节数)
        │     └────── 协议标识 Protocol ID=0x0000 (恒0, Modbus)
        └──────────── 事务标识 TxID=0x9C4B (客户端自增, 用于匹配应答)

应答:  9c 4b 00 00 00 07 01 03 04 12 34 05 67
       TxID回显│ 长度7│FC回显 字节数4 数据=0x1234,0x0567

异常应答: 9c 4b 00 00 00 03 01 83 02
                            │  │  └ 异常码02=Illegal Data Address(点表配错!)
                            │  └ FC|0x80 标记异常
【读帧四步法】TxID匹配?→PID=0?→FC=?→按FC查数据布局。90%的联调问题
(地址错/字节序错/数量超限)都能在这一眼扫描中现形。

47.3Modbus RTU 手工解析 + CRC 校验演示

TEXT
原始字节: 01 03 00 6B 00 03 [CRC_LO CRC_HI] = 01 03 00 6B 00 03 76 87
  01      从站地址1
  03      FC3
  006B    起始地址107
  0003    读3个寄存器
  76 87   CRC16 低字节在前！(多项式0xA001反射, 初值0xFFFF)

手算校验流程(面试常考):
  crc=0xFFFF
  依次异或每字节后循环8次: 最低位1?→右移再异或0xA001 : 仅右移
  最终取 crc 低字节在前附尾。
  用 python 一行验证: import libscrc; hex(libscrc.modbus(b'\x01\x03\x00\x6b\x00\x03'))

47.4EtherCAT 与 CAN 帧速览

  • EtherCAT：Ethertype 0x88A4 直载；帧体为若干 Datagram：[Cmd(1) Index(1) ADP(2) ADDR(4) Len/Type(2) IRQ(2) DATA...]；从站寻址常见「自增位置寻址」(POS) 与「节点配置寻址」；Wireshark 已内置 dissect 完整解析 —— 对照第45章原理看「一帧多报文」最直观。
  • CAN 标准帧：SOF | 仲裁ID11bit + RTR + IDE + r0 | DLC | DATA0~8 | CRC15 | ACK | EOF。用 candump/canguru 或逻辑分析仪解码；关注采样点配置一致性与错误帧位置（45章 bus-off 排查的证据来源）。

47.5分析功力提升五条

  1. 先留基线：系统健康时抓 10 分钟正常包归档 —— 故障时 diff 对比胜过一切猜测；
  2. 双端对抓：怀疑丢包时在两端同时抓，比对序号即可二分定位是哪一段丢的；
  3. 时间戳纪律：全网 NTP 对时 + pcap 用硬件时间戳，否则跨设备时序分析全是误导；
  4. 统计先行：Conversations 看 Top Talker、IO Graph 看突发、Expert Info 汇总重传/校验和错；
  5. 串口也要「抓」：485 用逻辑分析仪(Saleae 协议解码) 或双串口监听器，别靠肉眼数脉冲。

47.6八个真实排故案例（现象→定位→根因→对策）

#现象定位过程根因与对策
1全车间 PLC 周期性卡顿，CPU 占用飙高Mirror 口抓包 → IO Graph 发现组播洪水 300k pps；Conversations 锁定一台新装摄像头IGMP Snooping 未启用，未知组播泛洪到所有口。开启 snooping + 配置查询器根治
2某从站每天随机失联几分钟持续 ping + arpwatch 记录 MAC 漂移IP 冲突（临时接入的笔记本静态 IP 撞车）。建立 IP 台账 + DHCP Snooping 防再犯
3485 网络 CRC 错误率随温度升高而上升示波器看空闲电平：无偏置时 A/B 电平漂移不定，长 0 后起始位误判主机未接失效保护偏置电阻。加装 560Ω×2 上拉下拉后归零
4环网演练切换时伺服报警停机抓包测得 MRP 切换 180ms，而主站通信超时设 100ms参数不匹配。统一规划：超时 > 切换时间 ×2，并复测
5千兆口协商成半双工百兆且大量碰撞ethtool 看协商状态；换线对比水晶头只压了 4 对中的 2 对（劣质做工）。强制千兆前先修物理层——永远先怀疑线
6光纤链路误码率随昼夜波动光功率计实测收光 -28dBm（规格下限 -24）接头污染+弯曲半径过小。清洁端面、整改走线，余量恢复至 -18dBm
7VPN 远程维护时 Modbus 能连不能读大数据块小包通大包断 → 典型 MTU 问题；ping -f -l 1472 定位隧道 MTU=1400分片被安全设备丢弃。调整 MSS clamp / 应用分包 ≤1400
8新装仪表一上电就烧 485 口万用表测两端「地」之间电位差高达 38VAC接地环路+共模超限。两端加隔离型 485 中继 + 机柜等电位联结改造

常见问题 FAQ（避坑指南）

Q1：Wireshark 打开显示 "check sum incorrect" 一大片？

多为 TX offload 导致本机发出的包校验和未填。编辑 → 首选项 → Protocols 关闭对应校验和验证即可，不是真错误。

Q2：镜像口抓到的包不完整/有性能影响？

① 出向带宽超过观察口速率必然丢包（换更高速率口或分流）；② 镜像本身消耗交换机 ASIC 资源，核心大流量设备慎开；③ 抓包盘用本地 SSD，避免 NFS 抖动。

Q3：怎么判断该抓哪一层？

沿用 25 章五层法：应用行为异常先抓应用协议（Modbus 事务）；连接不稳抓 TCP 重传/RST；彻底不通抓 ARP/物理层指示灯。每一层只回答「我收到了什么」，边界自然浮现。

47.7深潜：tshark 自动化字段提取（报表级分析）

BASH
# 从 pcap 批量导出 Modbus 事务三要素 → CSV
tshark -r mb.pcap -Y "mbtcp" -T fields \
  -e frame.number -e frame.time_epoch? frame.time_relative \
  -e mbtcp.trans_id -e mbtcp.func_code \
  -e modbus.regval_uint16 -E header=y -E separator=, > mb_report.csv
# 进阶: 用 python pandas 按事务ID配对请求/响应计算 RTT 分布 ——
# 把"抓包"升级成"通信质量监控指标"。

47.8深潜：用 SNMP 定位丢包方向

交换机端口计数器是「链路层心电图」：snmpwalk -v2c -c public sw_ip IF-MIB::ifXTable 关注 ifInErrors/ifOutDiscards/ifInUnknownProtos。丢包判定法：A→B 丢包时，若 A 口 OutDiscards 增长=本机出口拥塞；B 口 InErrors 增长=物理链路劣化；两端皆零但应用层丢=中间设备策略丢弃 —— 三步锁定责任段，避免甩锅式排障。

47.9排故案例补充（第9~10例）★

#现象定位过程根因与对策
9SOE 事件顺序记录与现场目击顺序相反，事故复盘失效比对各装置 SOE 时标：跨装置时钟差达 800msNTP 未部署、各控制器各自走时钟。部署 PTP/gPTP(或至少统一 NTP+毫秒级校准)，SOE 精度规格写进技术协议
10新增 VLAN 后 A 车间 PLC 与 B 车间 HMI 忽通忽断同交换机内通、跨交换机不通 → trunk 链路检查级联口 trunk 未放行新 VLAN ID。修正 allowed vlan 列表；建立"加网必改交换机台账"流程

47.10深潜：Wireshark IO Graph 实操五步

  1. Statistics → IO Graph，时间粒度先设 1s 总览再缩到 10ms 找毛刺；
  2. 叠加过滤曲线对比：tcp.analysis.retransmission(红) vs 正常流量(蓝) —— 重传尖峰与业务卡顿时刻对齐即实锤网络问题；
  3. X 轴切 Tick？换 "Advanced…" 加 Y 轴第二曲线 SUM(yfield) 统计字节数；
  4. 导出图形 CSV 归档进《网络体检报告》（L47-1）。
