C1 软 PLC 项目拷问链（把本项目写上简历前必背）

Q1 你的 PLC 扫描周期 10ms 是怎么保证的？抖动多大？

【答题框架】机制（CLOCK_MONOTONIC 绝对时间睡眠防漂移）→ 数据（30min 实测 avg/max/P99，引用 L20-1/L35 报告）→ 干扰源分析（日志IO/调度/NFS）→ 兜底（看门狗+安全输出）。有数字、有归因、有兜底 = 真做过。

Q2 如果上位机主站以 1ms 频率轮询你的 Modbus 从站，会发生什么？怎么改？

【要点】先算账：单请求 RTT ~3ms > 1ms → 请求堆积。方案分层：①协议层并发处理（连接池）；②映像区读操作无锁快照（seqlock/RCU 思想）；③推送代替轮询（事件触发上报）；④明确告知客户物理边界 —— 工程师的价值在给出可行域而非硬扛。

Q3 你的看门狗会不会误复位正常系统？如何验证？

【要点】三级防线设计回顾（34章）+ 喂狗双条件（进程活且 PL 心跳走）。验证方法：故障注入矩阵（kill/暂停调度/拔 PL 时钟），统计误动作率与漏动作率；超时留 2 倍裕量的依据。

Q4 DI 输入为什么在 PL 做去抖而不是 Linux 里做？

【要点】确定性（硬件滤波不受负载影响）、事件不丢（锁存+W1C 对抗扫描相位差）、CPU 卸载。追问延伸：如果去抖参数要运行时可调怎么办？（寄存器化 DEBCYCLE —— 已实现）。

Q5 双机热备怎么做？说出你最先解决的三个问题。

【要点】①状态同步（映像区周期快照+序号，冲突仲裁策略）；②切换判据与脑裂防护（心跳多路径+仲裁者）；③输出侧无缝（主从 DO 硬件互锁或 PL 层仲裁开关）。能主动说「这是设计题，我需要先问 RTO/RPO 指标」是加分项。

Q6 EtherCAT 为什么比普通工业以太网快？

【要点】飞行的读写（帧过节点即处理转发，存储转发延迟消除）、分布式时钟(DC)亚微秒同步、拓扑灵活。对比 Modbus 主从轮询模型。引到自己路线图（SOEM 实验）最自然。

C2 系统设计题（白板架构能力）

Q7 设计一个「100 台电表数据采集网关」，要求断网不丢数。

【框架】需求澄清(协议/点表/频率/留存时长) → 南向采集池(Modbus 多会话+自适应超时) → 边缘存储(SQLite WAL 分级保留) → 北向队列(MQTT QoS1+水位补传) → 运维面(Web+OTA+看门狗) → 容量估算(写入 TPS vs SQLite 承载) → 失效模式清单。参考第41章 P2 蓝图展开。

Q8 为你的 PLC 设计 OTA 升级方案。

【要点】分区布局(A/B rootfs + 独立数据区) → uboot 计数回退 → 包签名校验(防变砖+防篡改) → 断点续传 → 回滚演练流程。至少答出「绝不原地覆盖唯一系统镜像」这条底线。

Q9 设计多协议转换器（Modbus↔OPC UA↔MQTT），谈谈数据建模。

【要点】核心抽象：统一信息模型（tag 字典+类型系统）居中，各协议做成可插拔南/北向适配器；语义映射表配置化；一致性由单一真源映像区保证。展示「协议是无所谓表皮，模型才是资产」的认知。

C3 行为面试与反问环节

Q10 讲一个你遇到的最难的技术问题。（STAR 法则示范）

【模板】S:PLC 偶发输出毛刺，现场三天两次 / T:定位并根治 / A:按五层二分——ILA 抓到 DI 锁存被 W1C 过早清除的窗口竞态 / R:改为事件置位保持语义，回归 500 次零复发，并把该模式写进团队检查清单。重点展示排查路径的可复现性，而不是玄学运气。

Q11 你没有 X 经验/不是科班，凭什么胜任？

【要点】证据法回应：用课程产出物说话（6000 行代码、验收报告、性能数据）；展示学习系统的有效性（42章方法论）；承认差距并给出补齐时间表。忌辩解、忌空喊热情。

Q12 你和导师/同事在技术方案上冲突过吗？

【要点】结构：分歧事实→各自的依据→用实验数据裁决（如 A/B 测试扫描抖动）→结果与关系维护。体现「对事不对人 + 数据说话」。

Q13 反问环节问什么？（别浪费这个加分机会）

【推荐】①团队当前最大的技术痛点是什么？②这个岗位前三个月的成功标准？③代码评审与测试文化现状？④产品下一步架构演进方向？避免只问薪资加班 —— 问工作内容质量才显得你是来做事的。

Q14 你未来 3~5 年的规划？

【要点】绑定岗位路径：1 年内独立交付模块（对应 L2→L3 能力矩阵）→ 3 年成为某子系统 owner → 5 年方向二选一（专家线：实时系统/高速接口深耕；管理线：带小型攻坚团队）。展示你用过 42 章矩阵认真规划过。
